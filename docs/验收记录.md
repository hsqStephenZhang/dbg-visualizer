## 性能基线

测量命令：`python3 tests/integration/run.py --benchmark`。使用当前本地 debug 示例，时间包含主机协议处理和目标调用；单次测量不代表稳定性能承诺。

| 工作负载 | GDB | LLDB | 目标调用数 |
| --- | --- | --- | --- |
| 短摘要 100 次 | 25.886 ms | 228.125 ms | 各 100 |
| 128 个不同 Point 值 | 33.178 ms | 266.972 ms | 各 128 |
| 10000 元素 Bytes 的 10 个 64 元素页 | 3.213 ms | 21.692 ms | 各 10 |
| LLDB synthetic 连续读取首批 64 子项 | — | 测试页缓存复用 | 一次 CHILD_PAGE；另有长度查询 |

脚本会输出新的 JSON 测量值，允许后续比较。当前门槛以调用数量和有界数据量为准，不设置容易受机器负载影响的毫秒断言。

## 可复现检查

```sh
cargo fetch --locked
cargo fmt --all -- --check
cargo clippy --offline --workspace --all-targets -- -D warnings
cargo test --offline --workspace
python3 -m unittest discover -s tests -p 'test_*.py'
python3 tests/integration/build_profiles.py
python3 tests/integration/run.py --faults --core --benchmark
python3 tests/integration/codelldb.py --adapter /path/to/extension/adapter/codelldb
```

集成 runner 为每个 GDB/LLDB 子进程设置 45 秒外部时限；目标调用另有 GDB/LLDB 时限。core 与独立二进制测试只在各自新建的临时目录创建文件，结束后清理。

CodeLLDB 测试使用本机回环 TCP 连接和实际 adapter，不启动图形界面；验证的是与 VS Code 相同的 DAP 数据流程，不能替代所有编辑器 UI 行为测试。

## 设计收敛与限制

- 文档草案中的宏补充了必填 `name` 与可选 `aliases`，用于显式记录调试信息中的名称差异。无需 Python 字典和额外导出函数。
- 首版使用静态预留内存。摘要长度、分页数量、名称和类型名称均有上限；输出不足不自动重试。
- LLDB 的泛型名称查询可能失效，因此在需要时为当前根模块建立 DWARF 类型目录，以实际 canonical type 身份核对。类型目录按模块身份缓存，不把同名字符串直接当成同一类型。
- LLDB 的结构化 map 采用计划允许的 `[i].key` / `[i].value` 平铺表示。
- 本组件不预先递归遍历对象图，展开深度使用调试器的路径深度控制；共享对象不做全局去重。
- GDB 不缓存跨请求值；LLDB 只缓存 provider 页并检查执行代次和对象头。对无法观察的、影响自定义适配器的外部状态写入，必须显式 refresh，不声称任意内存写入都可自动检测。
- GDB 超时粒度为整秒，200 ms 配置实际向上取整为 1 秒。LLDB 使用微秒接口。二者都不能回滚 fmt 副作用。
- 有界存储不保证用户 fmt 无分配、无锁、纯或可恢复；可捕获 panic 与进程 abort 明确区分。
- 自动收集所有 trait、直接构造 Formatter、远程/跨架构、纯内存容器适配、多动态库与 proc-macro 扩展继续属于原计划的后续范围。
