# 调试可视化协议 v1

> 历史归档：v1 实现已按用户要求删除，以下源码路径与命令仅对应 Git 历史版本。当前使用[协议 v2](../协议-v2.md)。

实现位置：`crates/visualizer-runtime/src/protocol.rs`、`lib.rs` 和 `debugger/common/core.py`。

v1 支持 64 位小端 Linux 本地目标。所有跨边界结构使用 `#[repr(C)]`；Python 校验 ABI、结构大小、指针宽度和字节序，不使用宿主机默认布局。未来扩展需要新版本或显式兼容策略。

## 发现与调用

唯一执行入口：`unsafe extern "C" fn dbgvis_dispatch_v1(request_addr: usize) -> u32`。

导出只读 `DBG_VIS_MODULE_V1`，总长 112 字节：

| 偏移 | 字段 | 编码 |
| --- | --- | --- |
| 0 | magic | 8 字节 `DBGVIS01` |
| 8 | abi、size、pointer_width、little_endian | 4 个 u32：1、112、8、1 |
| 24 | entry_size、request_size、response_size、child_size | 4 个 u32：112、88、48、304 |
| 40 | entries、entry_count | 2 个目标机器字 |
| 56 | request、response | 2 个目标指针 |
| 72 | output、output_capacity | 输出地址及容量 |
| 88 | children、children_capacity | 描述符区地址及数量上限 128 |
| 104 | dispatcher | C ABI 函数地址 |

GDB 可通过 minimal symbol 取得 descriptor 地址；LLDB 从主模块数据符号取得地址。读取元数据不执行目标函数。首版只接收可执行程序中的根注册表，不处理多个动态库注册表。

请求只能写入公布的 request 邮箱；dispatcher 拒绝其他请求地址。调试器必须串行提交并在目标停止时写邮箱，不能在已有调用执行中重写。Rust 用非等待原子标志保护执行，嵌套调用返回 BUSY。

## 注册条目

每条 112 字节：

- 三组 `(pointer, length)` 静态 UTF-8 文本：规范名、GDB 别名、LLDB 别名，共 48 字节。
- `size`、`align`、`capabilities`、`shape`，每项 8 字节，共 32 字节。
- 四个模块内部可选函数指针：Debug、Display、count、page，共 32 字节。

能力位：Debug=1、Display=2、Children=4。shape：struct=0、sequence=1、map=2。具体回调只由同一 Rust 模块内 dispatcher 调用，不构成稳定的 Rust 插件 ABI。类型 ID 为数组索引，仅对当前注册表有效；不使用 TypeId 或未校验的类型名哈希。

描述符区和条目结构大小构成 v1 适配器版本约束；改变子项语义需更新 ABI。没有单独的第三方私有容器布局版本，因为内置适配器调用容器公开接口。

## 请求与响应

Request 为 11 个 u64，88 字节，顺序如下：

```text
abi, size, sequence, operation, type_id, object,
mode, alternate, capacity, start, count
```

operation：FORMAT=1、CHILD_COUNT=2、CHILD_PAGE=3。mode：Debug=1、Display=2；0 仅可用于不格式化的元素查询。alternate 为 0/1。

`capacity` 约束摘要字节数，FORMAT 要求 1 到输出区上限；`start/count` 是逻辑元素偏移与数量，CHILD_PAGE 要求 count 为 1–64，拒绝越界和加法溢出。最后一页可以少于 count。空容器从 start=0 查询可返回零个元素。

Response 为 6 个 u64，48 字节：

```text
sequence, status, written, total, returned, shape
```

`written` 是 UTF-8 有效前缀字节数，不要求 NUL 结尾，允许内嵌 NUL。`total` 是容器逻辑元素总数；`returned` 是本页描述符数，对 map 等于本页逻辑元素数的两倍。每次操作清空响应的计数语义；失败响应不得作为上一轮结果使用。

调用者验证返回整数状态与 response.status 相同、sequence 对应本次请求，再按长度复制结果到调试器内存。复制完成前不得发起下一次调用。BUSY 不改写外层调用的响应，因此必须优先处理该返回码。

## 子元素描述符

每条 Child 为 304 字节：

| 字段 | 大小 | 语义 |
| --- | --- | --- |
| name | 64 字节 | UTF-8、零结尾；序列可留空，由前端填索引 |
| type_name | 192 字节 | UTF-8、零结尾的 Rust 类型名 |
| address | u64 | 实际目标对象或字段槽地址 |
| size、align | 各 u64 | 实际类型大小、对齐 |
| kind | u64 | 0=有类型地址；1=内联无符号标量；2=带字符串辅助信息的 &str 槽 |
| data、length | 各 u64 | 标量数据，或 kind=2 的字符串数据地址和字节长度 |

kind=2 的 `address` 指向实际 `&str` 字段槽，不能用 data 替代它传给针对 `&str` 的格式化函数。辅助字符串读取最多 4096 字节；有可信调试类型时，优先构造有类型的子节点。

map 子项按 key、value 交替排列，名称分别为 `key`、`value`。所有文本字段及页存储有固定上限；不允许截断类型名称，不允许泄露临时局部值的地址。调用者必须在恢复运行或对象布局变化后丢弃描述符。

## 状态码

| 值 | 名称 | 意义 |
| --- | --- | --- |
| 0 | OK | 成功 |
| 1 | TRUNCATED | 输出不足，已保留合法 UTF-8 前缀 |
| 2 | UNSUPPORTED | 类型没有对应能力，或无法表示描述符 |
| 3 | INVALID_REQUEST | 参数、对象基本地址检查或分页结果不合法 |
| 4 | ABI_MISMATCH | 请求版本或结构大小不兼容 |
| 5 | BUSY | 已有调用正在执行，不覆盖其响应 |
| 6 | FORMAT_ERROR | 没有截断，但 fmt 返回错误 |
| 7 | PANIC | 捕获到可展开 panic |

超时、无地址、core dump、内存读取失败和进程退出属于 debugger 后端错误，不伪装为 Rust 状态码。检查对齐和类型名称不能证明地址有效，也不能证明暂停时对象不变量成立。
