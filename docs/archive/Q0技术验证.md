# 第二阶段 Q0 技术验证记录

日期：2026-09-10。状态：**历史 Q0 证据；工具链决策已解决。** 用户随后批准 nightly specialization、GDB 优先、不保留 v1，当前核心及真实后端结果见[第二阶段验收记录](../第二阶段验收记录.md)。下面记录决策前的独立实验，不将它们冒充整个第二阶段验收。

## 1. 实际运行方式

```sh

# 独立 nightly 实验及真实 GDB/LLDB 子进程；需要本地 ptrace 权限。

```

已实际运行第二条命令，退出码 0。runner 校验每项预期成功/失败、具体错误码和输出标记；所有编译产物位于独立临时目录。没有修改默认工具链、workspace 依赖或当前 v1 runtime。

测试工具链为 stable rustc 1.97.1 与 nightly rustc 1.99.0-nightly (12c36e253 2026-08-10)。这是本地实际安装版本，不表示已验证其他版本或远端 CI。

## 2. Stable 原型未满足泛型自动优先级

源文件：[autoref.rs](q0/autoref.rs)、[overlap.rs](q0/overlap.rs)。

同一 Both 类型同时具有 Visualize 与 Debug。使用 autoref 方法解析候选，在具体调用点选中 Visualize；在 `fn generic_debug<T: Debug>` 内则选中 Debug，即使实际传入 Both，也不会在单态化时重新选成 Visualize：

```text
CONCRETE=visualize:Both
GENERIC=debug:Both
AUTOREF_GENERIC_PRIORITY_LOST
```

没有约束的 `fn generic_unbounded<T>` 则报 E0599，无法调用任何候选。分别对 `T: Debug`、`T: Display` 实现同一总括 trait，报 E0119（重叠实现）。这些结果证实这两种常见技巧不能满足计划中的通用泛型契约；不把它们包装成只支持具体字段的“已完成实现”。

这不构成对所有可能 Rust 程序的形式化不可能性证明，但当前未获得可满足完整契约的稳定版实现路线。proc-macro 的 token 输入与 TypeId 不会自动补上这种泛型能力选择。[Rust 方法解析](https://doc.rust-lang.org/reference/expressions/method-call-expr.html)、[trait 一致性规则](https://doc.rust-lang.org/reference/items/implementations.html#trait-implementation-coherence)

## 3. 独立 nightly 分派实验

源文件：[dispatch.rs](q0/dispatch.rs)、[consumer.rs](q0/consumer.rs)。前者单独编译成 rlib，后者作为另一个 crate 引入，因此不是把所有具体类型放在同一个宏调用点的假泛型测试。

使用 `#![feature(specialization)]`，通过三个独立的特化层按 Visualize → Debug → Display 选择，不使用 unsafe 类型转换、TypeId 哈希、私有布局或 `'static` 约束。实验只验证调用选择，用普通 String 收集断言文本；尚未接入有界 formatter、proc-macro、v2 mailbox 或调试器前端。

debug 与 opt-level=3/fat LTO 两组实际构建均通过：

- Visualize-only、Debug-only、Display-only、Debug+Display、三者齐全的正确选择。
- 三者齐全时低优先级实现包含 panic，实际不会被调用。
- Vec 的单能力元素及优先级；HashMap 的嵌套 Vec；HashMap 的 unit key、Display-only value 与 BuildHasherDefault 策略。
- 另一个 crate 定义的 `Wrapper<'a, T, Policy, const N: usize>`；借用局部 String 的 str、不实现任何格式化 trait 的 PhantomData Policy、const 参数 13。
- `Vec<NoTraits>` 的构建报 E0080，消息明确指出没有 Visualize/Debug/Display，而不是运行时返回缺失能力。

### 重要限制

缺失能力检测依赖关联常量在代码生成时求值。实际 `rustc` 构建能拒绝无效具体实例，但 `--emit=metadata` 检查会通过，不能声称 `cargo check` 已提供同样诊断。runner 明确输出 `NIGHTLY_METADATA_ONLY_DOES_NOT_REJECT_*`，保留这个差异。

这只是隔离的实验性候选后端。specialization 仍是 nightly 功能，stable 编译该实验报 E0554。不能在没有确认的情况下把它设为项目默认要求；尚未验证完整 derive、递归循环检测、字段属性、feature 关闭与分发兼容。[Rust specialization](https://doc.rust-lang.org/unstable-book/language-features/specialization.html)

## 4. Typed anchor 初步验证

源文件：[anchor.rs](q0/anchor.rs)、[GDB 验证脚本](q0/anchor_gdb.py)、[LLDB 验证脚本](q0/anchor_lldb.py)。

用一个带 slot 和 `*const T` 字段的不可变静态 anchor 引用具体类型，typed 字段为空指针且从不解引用。通过可达 black_box 引用保留 anchor。GDB/LLDB 读取它的类型信息，再与断点处变量的真实调试器类型比较，不调用目标格式化函数进行发现。

stable 构建的 debug、release 等效 opt-level=3/fat LTO 两组测试均通过，类型包括：

- 默认泛型参数的 HashMap<String, Vec<u64>>。
- unit key 与 ZST BuildHasherDefault 的 HashMap。
- 实际借用局部 String 的 Borrowed<'a, Zst, 17>。
- ZST 本身。

GDB 需同时尝试 global/static symbol lookup：Rust 静态变量仅使用 `lookup_global_symbol` 无法找到，但 `lookup_static_symbol` 可找到。LLDB 可通过 `FindFirstGlobalVariable` 获取对应 anchor。

### 同布局 const 实例及同名类型的后续验证

在原有 fixture 中增加 `Borrowed<'a, Zst, 19>`，与 const 参数 17 的实例同时保留；另增加字段布局相同的 `left::State(u64)` / `right::State(u64)`。实际重跑 `python3 docs/archive/q0/run.py --debuggers`，debug 与 fat LTO 结果一致：

- GDB 的类型身份比较可以区分 const 17/19，也能区分不同模块下的两个 State。
- LLDB 可区分不同模块的 State，但不能完整解析本例第二个 Borrowed const 实例。其 anchor pointee 显示为 `void`，变量 canonical type 名称为空；不能据此构造可信类型。
- 验证脚本保留并明确报告这个失败边界，将该条目排除出可用类型集合，而不是通过删除测试、按大小匹配或强制转换来“通过”。当前输出包含 `LLDB_CONST_GENERIC_UNAVAILABLE_MUST_REJECT BORROWED_OTHER 'void' ''`。

`LLDB_TYPED_ANCHOR_OK` 只表示仍可关联的类型通过检查，**不代表所有 const 泛型已支持**；runner 同时打印拒绝项。此处还不是完整前端的回退验收。后续应研究唯一非泛型 anchor 或其他调试信息关联方案；不能回到只按相同名称和大小匹配，更不能在信息不完整时调用错误类型的函数。

目前尚未覆盖同名不同 crate/版本、所有生命周期擦除形式、优化掉的值、CodeLLDB DAP 和不同目标平台。Q0 类型关联仍未完全验收。

## 5. 决策记录（已解决）

原计划要求 stable 默认及跨 crate 泛型自动选择。stable 原型未满足后一要求，nightly 实验提供可行性证据，但需要用户批准工具链变更。

用户已经明确批准采用 nightly specialization，并明确不保留 v1。现在 nightly 是启用 dbgvis 时的唯一后端，GDB 是本轮前端；不再等待 stable 路线或 LLDB const 类型关联通过。derive、有界 formatter、v2 注册、通用 HashMap、第三方类型和泛型矩阵已进入核心验收。

未来若重新要求 stable，需要独立研究或调整契约；本轮没有缩减为“所有字段必须 Debug”或“第三方字段必须 via”。
