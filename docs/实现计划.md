## 1. 产品目标与方向调整

让用户像使用 Serde 一样，为自有类型添加 derive；尚未实现 Visualize 的第三方字段自动回退到已有 Debug/Display，即可在 GDB 中看到递归格式化后的**逻辑值字符串**。HashMap 应显示键值内容，复杂泛型、零大小策略对象和内部存储结构不应成为用户编写 visualizer 的负担。LLDB/CodeLLDB 延后，不作为本轮验收前提。

这一轮不以“继续补充 Bytes / IndexMap 专用代码”为目标，而以“一个新的消费项目，无需修改框架即可接入新类型”为目标。

核心决策：

1. proc-macro 是主要用户接口，负责 derive、字段策略、Debug/Display 桥接声明和根类型注册。
2. 默认字段选择顺序为 **显式字段配置 > Visualize > Debug > Display > 编译报错**，采用 nightly 的三层 specialization 分派。普通字段三者均不可用时在具体实例的代码生成阶段报错：需 `cargo build`，不承诺 `cargo check` 检出。显式 via/根模式仍有普通 trait bound 检查。
3. 新增 serde 风格的 `Visualize` 递归协议，直接流式写入有界文本区，不构建完整中间对象树。
4. 一次根对象请求，在 Rust 内完成递归，返回一个字符串快照。用户不实现 `count/page`，不维护子节点地址，不配置分页。
5. 使用构建内 TypeId 及注册句柄；不要求 ID 跨编译器、跨构建或跨进程稳定。
6. 对外提供一个 facade crate 和配套安装工具，不让消费项目复制 Python 或本仓库的 `build.rs`。
7. 保留 native 回退、执行授权、有界输出和故障隔离；“便捷”不意味着加载脚本后默认执行任意目标函数。
8. a、b、c 的 Visualize 实现通过 trait 静态递归组合；非泛型 derive 同时产生根登记，linkme 自动汇集到主程序，main 只需无参数 enable。泛型/第三方根按具体实例登记。暂不实现第三方 adapter、remote derive、getter 映射或 Serde bridge。
9. 生产消费项目可提供默认关闭的 visualize feature，并向 a/b/c 传递；关闭时不包含可视化初始化、注册表、dispatcher 或预留缓冲区。仓库 examples/demo.rs 为简洁演示，按用户要求直接 derive、始终启用，不设 feature gate；开关契约由独立消费项目测试。运行时 manual/automatic 是另一层开关。

Rust 调查指出值展示、变量打印及 visualizer 维护成本是主要问题，并提出复用 Debug 的方向。本计划据此优先降低类型作者和使用者的接入成本，不将 async 单步或堆栈重建纳入此次目标。[Rust 调试调查](https://blog.rust-lang.org/2026/09/07/rust-debugging-survey-2026-results/)

### 1.1 与第一阶段的区别

| 方面 | 历史 v1（已移除） | 第二阶段方案 |
| --- | --- | --- |
| 接入自有类型 | 手写注册和字段枚举 | 非泛型 derive 自动登记，linkme 汇集 |
| 接入第三方类型 | trait 可复用，展开需手写 unsafe adapter | 普通字段自动回退 Debug/Display；支持显式覆盖 |
| 跨 crate 组合 | 显式根注册与手写字段枚举 | 各 crate derive，应用根对象静态递归组合 |
| 容器 | 特化的 Bytes / IndexMap 分页 | 泛型序列、映射和递归组合 |
| 类型定位 | 手工完整类型名和别名 | 宏生成元数据及 typed anchor，自动关联注册句柄 |
| 输出 | summary + 有地址的 children | 默认完整或明确截断的文本快照 |
| 用户限制设置 | 容量、页大小、元素数等 | 好用的默认值；高级字节、深度和节点预算 |
| 安装 | 仓库脚本与示例构建流程 | crate 内置产物 + 项目级 setup / doctor |

文本快照不等于 IDE 可编辑、可逐项展开的值树。新路线保留调试器 native children，不把文本解析回假造的 Rust 子对象。v1 structured children、分页命令、适配器及 LLDB 专用脚本已经移除；需要旧版时从 Git 历史获取，不在 v2 中维持兼容层。

## 2. 目标用户 API

以下核心语法已实现，facade 为 `dbgvis`，但尚未发布到 crates.io；当前通过本地 path 依赖使用。安装工具示例仍是后续目标，不是已可执行的命令。

### 2.1 自有类型：derive 递归格式化

```rust
use std::collections::HashMap;
use dbgvis::Visualize;

#[derive(Visualize)]
struct Record {
    name: String,
    tags: HashMap<String, Vec<Option<u32>>>,
    #[dbgvis(skip)]
    implementation_cache: InternalCache,
    #[dbgvis(rename = "state", via = "debug")]
    status: ExternalStatus,
}

#[dbgvis::main]
fn main() {
    // 正常业务代码；宏注入启用和保留入口。
}
```

预期文本形态：`Record { name: "demo", tags: {"kind": [Some(1), None]}, state: Ready }`。HashMap 项顺序遵循实际迭代顺序，不为美观排序或要求 key 实现 Ord。

derive 支持命名结构体、元组结构体、unit、enum 当前变体、泛型、const generic 和借用字段。生成代码只访问实际字段/匹配活动变体，不让调试器解码 enum 或私有布局。

`#[dbgvis::main]` 是便捷入口而非强制要求，等价于函数体开头的 `dbgvis::enable!()`，两者不再接受注册集合参数。没有任何泛型参数的 derive 默认登记 auto 根；泛型 derive 仅提供递归实现。类型级 `#[dbgvis(no_register)]` 可关闭自动根登记。不能默认 main 宏与所有 async runtime 宏兼容。

### 2.2 第三方根类型：只接入已有 Debug/Display

```rust
dbgvis::register_type!(std::collections::HashMap<String, Vec<u64>>; debug);
dbgvis::register_type!(third_party::SomeType; debug, display);

#[dbgvis::register] // 只登记，不生成 Visualize；无参数时使用 auto
#[derive(Debug)]
struct Foo { x: i32, y: String }

#[dbgvis::register(debug)]
type Borrowed<'a> = indexmap::IndexMap<&'a str, u32>;
```

只声明实际存在的能力；缺少 trait 时在编译期指出对应条目。不手写调试器类型字符串，不为上述类型实现外部 trait，不新增 Python 分支。

标准 derive(Debug) 本身不产生元数据，需要 register 属性。属性宏和函数式宏共用宏命名空间，因此实际 API 为 `#[dbgvis::register]` 与 `dbgvis::register_type!`，不同时导出两个同名 register 宏。`register_type!(T; modes...)` 的分号后可指定能力和 default。对既 derive Visualize 又需显式根模式的类型，先加 no_register 再加 register 属性，避免重复登记。

标准 HashMap 的 Debug 已可表达键值内容；若当前看到内部布局，直接复用它通常就是最短路径。需要字段控制或递归预算时，再使用内置 HashMap 的 Visualize 实现。不要为了展示 HashMap 重写哈希表布局解析。

### 2.3 第三方字段：默认自动回退，显式配置优先

```rust
#[derive(dbgvis::Visualize)]
struct State {
    a: a::State,                  // 已实现 Visualize：递归输出
    value: third_party::Value,     // 只有 Debug：自动使用 Debug
    label: third_party::Label,     // 只有 Display：自动使用 Display
}

#[derive(dbgvis::Visualize)]
struct Valid {
    #[dbgvis(via = "debug")]
    value: third_party::Value, // 强制 Debug，编译期要求 Debug
    #[dbgvis(via = "display")]
    label: third_party::Label, // 强制 Display，编译期要求 Display
}
```

自动选择顺序固定为 Visualize > Debug > Display。Debug 优先于 Display，以调试状态展示为默认用途；即使类型同时具有多种能力，也不让链接顺序或注册顺序决定结果。三种能力均不可用且没有 skip 的字段编译失败。上述选择不意味着为每个 Debug 类型实际实现 Visualize，而是生成或选择对应的格式化调用。

自动选中或显式指定 Debug/Display 都是**整值委托边界**：该值内部完全遵循被选中 trait 的实现，不会自动切回内部元素的 Visualize。在 Vec 字段上显式 `via = "debug"`，就委托整个 Vec。对于框架内置的 Vec/HashMap 递归路径，目标是元素层也遵守同一自动选择规则；`Vec<External>` 和 `HashMap<String, External>` 不能因为元素只有 Debug/Display 就要求用户补 via。这个泛型行为是 Q0 必须证明的技术门槛，本阶段仍不提供用户侧第三方 adapter 组合器。

第三方字段的自动回退不依赖将其预先登记成根类型。三种能力均不存在的错误不能推迟到调试时查表处理，也不能用 native 回退掩盖。暂不支持 remote derive、getter 映射、自定义第三方 adapter 和 Serde Serialize 桥接。

**回退只表示调用前选择能力，不表示执行失败后重试。** Visualize/Debug/Display 一旦选定，遇到 panic、格式化错误、超时或预算截断，都保留其错误/截断语义，不再尝试低优先级实现。不能把一次查看变成多次有副作用的目标执行。

### 2.4 字段策略与 trait 冲突

第一批属性仅包含：`skip`、`rename`、`transparent`、`via = "debug"`、`via = "display"`、显式 `bound`。秘密字段可跳过，默认不读取被跳过的字段；不提供 `with` 或 getter 属性。

| 字段声明 | 编译期要求 | 输出行为 |
| --- | --- | --- |
| 普通字段 | Visualize、Debug、Display 至少一种可用 | 按该顺序选用；Visualize 递归，其余委托 |
| `via = "debug"` | 字段类型实现 Debug | 委托 Debug 的完整字段输出 |
| `via = "display"` | 字段类型实现 Display | 委托 Display 的完整字段输出 |
| `skip` | 不要求格式化 trait | 不访问、不输出该字段 |

derive 按实际参与输出的字段生成正确的能力选择与约束，不对普通字段直接强加 Visualize，也不要求它同时满足三种 trait。skip 字段或仅作为 PhantomData/容器策略的泛型参数不应被添加多余格式化约束。泛型声明可以保留条件实现；不满足条件的具体实例在编译其使用/根注册时失败，不要求每个泛型定义本身立即报错。

显式 `via` 覆盖默认优先级；即使存在其他 trait，被指定的 trait 不存在仍编译失败。互斥属性组合在编译期报错。不要直接实现 `impl<T: Debug> Visualize for T` 与多个重叠 blanket impl 来模拟优先级，否则会与容器、derive 和专用实现冲突。[Rust trait 一致性规则](https://doc.rust-lang.org/reference/items/implementations.html#trait-implementation-coherence)

proc-macro 处理被标注项的 token，再由编译器完成类型检查；它不是全程序反射，不能自动枚举依赖里所有类型及所有泛型实例。[Rust procedural macros](https://doc.rust-lang.org/reference/procedural-macros.html)

稳定版 autoref 原型不能满足泛型优先级，证据见 [Q0](Q0技术验证.md)。本轮已获准用 full specialization：三个内部 trait 分别负责 Visualize、Debug、Display 的特化选择，避免在同一层建立互不包含的 Debug/Display 重叠实现。TypeId 不参与逐字段反射，也不能生成缺失的机器码。specialization 仍是未稳定能力；项目使用 nightly，并记录实际验证的编译器版本，不承诺任意 nightly、生命周期敏感的特化或 stable 兼容。[Rust specialization](https://doc.rust-lang.org/unstable-book/language-features/specialization.html)

### 2.5 跨 crate 组合：derive 与根注册分离

设 a、b、c 分别提供派生了 Visualize 的公开类型；main 所在应用仅需组合它们：

```rust
#[derive(dbgvis::Visualize)]
struct AppState {
    a: a::State,
    b: Vec<b::Item>,
    c: std::collections::HashMap<String, c::Entry>,
}

#[dbgvis::main]
fn main() {
    // 构造 AppState 并在使用它的位置设置断点。
}
```

格式化路径为 `AppState::visualize → 字段/容器的 Visualize → a/b/c 的 Visualize`，共享同一上下文和缓冲区。a、b、c 不必导出注册集合，也不必在各自库中调用 enable。其私有字段由定义 crate 内生成的实现处理，应用无需获得字段访问权。

derive 决定如何格式化；根登记决定调试器从哪里进入。非泛型 b::Item 的 derive 自动登记后可直接打印，不需 main 重复声明；泛型类型实例或 no_register 类型需要独立打印时仍须显式登记。嵌套代码通过正常 trait 引用保留，不依赖逐字段 TypeId/linkme 查表。

要遵守上述字段策略，应使用默认 auto 选中的 Visualize，或显式登记后选择 visualize 模式。根 Debug/Display 模式完全委托对应 trait，不应用 Visualize 的 skip/rename/via 属性。

a、b、c 必须使用同一个核心 Visualize trait 定义才能保留自定义递归语义。facade 重导出统一 runtime trait；不兼容版本的同名 trait 不互通。若一个值只实现另一版本的 Visualize，但存在本版本可调用的 Debug/Display，自动规则可能选中后者；这不属于 Visualize 版本互操作，不能宣称原字段策略仍生效。跨 crate 同版本组合与版本不一致诊断都要验证。

## 3. 递归格式化引擎：没有用户侧分页

已实现的核心接口：

```rust
pub trait Visualize {
    fn visualize(&self, out: &mut Formatter<'_>) -> Result;
}
```

Formatter 提供 record、tuple、variant、sequence、map 和文本叶子写入器。所有内置实现及 derive 通过共享上下文递归到字段/元素，直接写入同一个 bounded writer。不生成 JSON DOM、临时 Vec 或完整 String 后再截断，不从 Debug 文本反向解析类型。

一次 `FORMAT_VALUE` 完成根对象与其递归值的输出。Python 只读取文本和状态，嵌套元素不逐项调用 dispatcher，也不逐项查调试信息或导出地址。

### 3.1 限制与终止语义

- 默认请求容量沿用 4096 字节、编译上限沿用 64 KiB；允许用户调整。完整输出放得下时返回完整文本，否则返回合法 UTF-8 前缀及明确截断标记。
- 新增内部默认 `max_depth = 32`、`max_nodes = 4096`，由一次根请求共享，作为高级可调预算。序列迭代必须在调用下一次 `next()` 前检查剩余预算，不能先 collect，也不能在达到上限后继续计数剩余元素。
- 深度/节点到限输出省略标记，响应携带具体原因；容量不足时不承诺括号闭合或可机器解析。此输出是展示文本，不是序列化存档格式。
- 不自动扩容重试，不后台遍历剩余页；用户显式提高预算后才重新执行。没有“通过取消分页就无界遍历”的默认模式。
- 框架生成的递归路径服从所有预算；直接 Debug/Display 或用户手写 Visualize 中的任意代码只能约束写入，不能保证计算量、分配量或内部递归深度。继续使用后端超时，并在文档及 doctor 中说明限制。

### 3.2 引用、循环和零大小类型

- `&T`、Box、Rc、Arc 等受支持的安全引用/所有权包装可递归到值，不展示引用计数器等内部布局。原始指针默认只显示地址，不自动解引用；任意 `dyn Trait` 不承诺自动识别具体类型。
- 循环检测使用当前递归路径，不全局去重共享值；深度/节点限制是最终兜底。不可只用对象地址判重：ZST、多字段同址及胖指针都会使这种策略误报。
- `()`、unit struct、PhantomData、ZST key/value 和 ZST hasher/allocator 策略均须测试。只对合适的非零大小引用节点使用地址与类型/视图身份组合判环；ZST 不按地址认定循环。`&str` / slice 通过 Rust 借用处理其元数据，不向 Python 拼装胖指针。
- 不自动获取 Mutex/RwLock 的阻塞锁，不执行惰性迭代器/Future。需要这些视图时使用明确的非阻塞适配或摘要，另行声明行为。

## 4. TypeId、根类型识别与注册组合

### 4.1 接受构建内身份，不设计稳定类型 ID

采用 `std::any::TypeId` 做 Rust 内的类型/注册身份及去重。注册表允许为具体 `'static` 类型保存 TypeId；不使用它们在不同构建间比较、持久化配置或复用缓存。重建程序、更换目标或重启后重新发现注册表。

当前协议使用进程/主模块身份和整数 slot；注册表在 enable 后不可变，无动态更新代次。TypeId 留在 Rust 内，不要求 Python 解码私有布局，也不把哈希当作无碰撞身份。`Registration<T>` 固定目标类型与各函数关系，不能混搭另一 U 的函数。

TypeId 的 `'static` 约束需要单独处理，它与“ID 是否稳定”无关。递归 `Visualize` 不继承 Any 或 `'static`；借用值全程保持调用内借用。2026-09-12 实现：marker TypeId 标识登记入口，独立的具体类型 TypeId 决定是否可合并。带生命周期的根由宏对自由生命周期替换为 `'static` 后取得类型身份，回调仍保持生命周期泛化；身份生成不会把实际对象转换成 `'static`。同名同布局仍不构成类型相等证明。[TypeId 官方文档](https://doc.rust-lang.org/std/any/struct.TypeId.html)

### 4.2 TypeId 不能代替“调试器变量 → 注册入口”桥接

普通 Rust 对象不携带 TypeId，DWARF 类型也不能由 Python 直接转换成 Rust TypeId。需要生成可验证的关联，但不把这项工作推给用户。

Q0 优先验证 **typed anchor**：为每个注册项保留引用具体 `T` 的静态元数据/类型锚点，将调试器里的真实类型对象与对应 slot 关联。发现过程中只读符号和调试信息，不为了确定类型而猜测调用对象方法。验证类型别名、默认泛型参数、同名不同 crate、同布局不同类型、ZST、release/LTO。

若某个后端不能从 anchor 可靠取得类型，允许框架自动生成名称候选并辅助核对模块/布局；歧义拒绝调用。若默认工具链不能实现可靠的零手工匹配，则在 Q0 记录阻塞并调整 anchor/构建产物方案，不能把用户填写完整名称当成“已完成自动接入”。高级别名覆盖仅用于诊断兼容。

nightly specialization 是本轮唯一自动回退后端，不保留 stable/v1 分支。`visualize` 项目 feature 控制是否引入整个 dbgvis 依赖；关闭后业务项目可以使用自己的 stable 工具链，不意味着启用 dbgvis 时也支持 stable。

### 4.3 注册范围与可组合性

- 无类型/const/生命周期参数的 derive 默认生成递归实现及 auto 根登记；任何泛型 derive 都不枚举实例。嵌套字段仍通过 trait 递归，不必逐个登记；第三方或泛型具体根用 register_type! 或 register alias。
- linkme 的 `VIS_TYPES: [fn() -> Root]` 收集静态工厂指针。应用 enable 遍历工厂、排序、检查重复并发布既有 v2 表；GDB 不解码 linkme 内部 section，也不调用工厂。工厂只生成元数据，不格式化对象。[linkme 官方文档](https://docs.rs/linkme/latest/linkme/)
- 不用 proc-macro 进程全局变量收集类型，也不让每个 derive 导出同名 dispatcher。同名根核对具体类型 TypeId 后合并能力；同名但不同身份拒绝，marker 不可用于不同类型。按类型名/anchor 名排序后保留首条默认模式和各能力首个入口。同作用域重复声明允许编译期符号冲突诊断。
- enable 在正常程序启动时准备注册句柄及元数据并保留函数；在 enable 前停住时回退并提示未就绪，不在任意断点隐式初始化。递归格式化期间不扩展注册表或抢全局初始化锁。
- 保留真实可达引用和最终二进制验证，不把 `#[used]` 当成最终链接保留保证。兼容无 main 宏的启动路径和 feature 完全关闭。

第一轮仍限定一个可执行程序内的注册表；跨 crate trait 递归组合是必做，多个根集合的组合与冲突处理单独验证。跨动态库发现/卸载不是它们的同义词，后者单列后续范围。

#### linkme 落地与验收

1. 宏产生 typed anchor、类型固定的 Registration<T> 工厂以及 linkme slice 元素；不要求消费方直接依赖 linkme，支持 dbgvis 依赖重命名。
2. 借用 alias 的静态 anchor 携带 DWARF 类型，其类型同时用于生成生命周期擦除后的 TypeId；工厂保持生命周期泛化，不强制业务 T: 'static。
3. 允许合并前 0–4096 个根。空表不会初始化失败；过多或身份冲突明确拒绝，同类型重复根合并。排序只用于稳定当前构建内的表，不承诺 slot 跨构建稳定。
4. 非泛型自动登记会保留格式化代码和类型元数据，增加构建体积；no_register 只取消该根入口。要完全消除宏、linkme、anchor、dispatcher 和缓冲区，使用项目级 feature。
5. 验证主程序、依赖库和函数内局部类型的锚点；特别检查已链接库中从未被业务代码引用的登记类型在 debug/LTO 下仍存在。只在 Cargo.toml 声明、未被链接的 crate 不保证出现；纯登记库应显式 `use dependency as _;` 并验证最终产物。
6. 此机制自动收集已生成的登记项，不自动发现全部 Debug 类型，不产生所有泛型单态化，不跨 runtime 版本或动态库自动合并。原集中式 visualizers/带参 enable/main 入口删除，不建立双重收集路径。

## 5. 通用类型覆盖与第三方接入边界

### 5.1 内置基础能力

| 类型家族 | 实现方式 | 必须验证 |
| --- | --- | --- |
| 数值、bool、char、str、String | 文本叶子及转义 | Unicode、NUL、边界值 |
| struct、tuple、enum | derive 与静态字段递归 | 泛型、活动变体、skip、transparent |
| slice、array、Vec、VecDeque | 泛型序列迭代 | 空值、嵌套、const generic、ZST 元素 |
| HashMap、BTreeMap | 公共 iter + 泛型 key/value 递归 | 不同 K/V、自定义 S、ZST K/V |
| HashSet、BTreeSet | 公共 iter + 集合文本 | 顺序语义、预算、无额外排序 |
| Option、Result | 当前变体和其中的值 | 嵌套容器、None/Err |
| 引用、Box、Rc、Arc、PhantomData | 明确的逻辑视图策略 | 共享值、引用循环、零大小标记 |

内置泛型实现仅添加公开 API 真正需要的约束；遍历所需约束不应无故包含 Debug、Clone 或 `'static`。不用不同编译器私有布局，不运行容器携带的任意策略对象来获取“显示形式”。

### 5.2 第三方接入范围（本阶段收敛）

1. 上游已实现 Visualize：作为普通字段直接递归，与 a/b/c 的组合规则一致。
2. 未实现 Visualize，但实现了 Debug/Display：普通字段自动选用 Debug、其次 Display；可用 via 强制覆盖。直接从调试器打印该类型仍需根注册，不修改上游或生成私有布局实现。
3. 普通字段三种能力均不可用，或显式字段/根声明要求的 trait 不存在：编译失败。只有公开 getter、迭代接口或 Serde Serialize 不足以接入；skip 字段是明确不输出的例外。

本轮不交付第三方 adapter 宏、remote derive、getter 映射、`with` 组合器、VisualizeWith trait 或 serde bridge。“像 Serde 一样”指 derive 与编译期递归约束的使用体验，不表示依赖 Serde 或覆盖其所有扩展机制。

Bytes/IndexMap 的 v1 分页实现删除。v2 用它们已有的 Debug 做回归，覆盖三组 IndexMap K/V/S 实例；新增 hashbrown::HashMap 作为真实第三方容器验证，以及独立 crate 的私有字段、Display-only 类型。无需给 runtime/Python 增加类型白名单。缺少三种能力的类型用代码生成失败测试验证。

## 6. 运行时与调试器协议

沿用 mailbox、bounded writer、串行调用、请求序号及失败隔离思路，使用全新的 v2 文本协议与导出符号；不兼容 v1。布局见[协议 v2](协议-v2.md)。

新主操作 `FORMAT_VALUE`：请求带注册 slot、对象地址、模式、alternate 和输出预算；响应带请求序号、状态、文本长度及截断/省略原因。保留目标指针宽度、字节序、能力和缓冲区边界校验。

输出模式区分：

- `native`：由现有调试器视图展示，本组件不执行目标调用。
- `debug` / `display`：准确复用对应 trait，不偷偷改写内部递归策略。
- `visualize`：执行 derive/内置容器组成的递归视图，字段按默认优先级自动选择，显式 via 优先覆盖。

`dbgvis print value` 在配置为 native 时默认采用条目的默认视图。无模式属性的条目登记 `auto`（内部优先 Visualize > Debug > Display）；多能力支持 `default = "..."`，未指定按 `auto > visualize > debug > display` 选择已登记的第一个能力。显式 `--mode` 严格要求登记该能力；`--mode auto` 表示条目默认模式，不自动暴露未登记的其他 trait。

自动变量摘要只为已注册且被项目启用的类型安装 formatter；`execution=manual` 仍是默认值。建议 setup 提供显式的项目级 automatic 选项，安装行为本身不能被视作执行授权。

一次根请求最多一次 dispatcher 调用；一次 UI 刷新可能有多个根值，按值计数。前端展示快照及诊断，原生子树保持独立。常规文本路径不创建 CHILD_COUNT/CHILD_PAGE 请求，不维护 Rust 元素地址缓存，也不为每个递归子值创建 SBValue。

初版文本结果不跨请求缓存，避免把同一停顿中的内存修改隐藏起来。若后续加入缓存，必须单独验证外部写值、目标调用和重启失效，不以 stop ID 未变断定值未变。

无地址或类型无法可靠关联时回退；包括被优化掉的根值。ZST 的逻辑递归不依赖元素地址，但也不能伪造一个根指针并声称根值仍存活。

panic、超时、重入、目标退出、abort 及 core dump 延续现有边界：unwind 可捕获不等于纯函数；中断不撤销副作用；无法确认 dispatcher 已返回时禁用该进程后续主动调用。core dump 只用 native/既有纯读内存视图，新递归格式化不可执行。

## 7. 打包、安装与分发体验

### 7.1 包结构

| 包/目录 | 职责 |
| --- | --- |
| `dbgvis` facade | 重导出宏、统一核心 trait 和 enable；消费方默认只引入它 |
| `dbgvis-macros` | derive、字段 via、register 属性、register_type!、main 属性及编译诊断 |
| `visualizer-runtime` | 递归 formatter、有界存储、类型注册及 dispatcher |
| 内置类型支持 | std 泛型实现默认提供；不引入第三方 adapter 包或 Serde 依赖 |
| `cargo-dbgvis` | 内置版本匹配的调试器资源，项目级 setup / doctor / uninstall |
| `visualizer-runtime/gdb.py` | 自包含 GDB v2 前端；不加入按第三方类型命名的分支 |

宏支持 Cargo 直接依赖重命名及 workspace 继承别名；不要求依赖名必须叫 `dbgvis`。本轮使用 nightly；实际验证 rustc 1.99.0-nightly (12c36e253 2026-08-10)，不设置虚假的 stable MSRV。nightly 升级需要重跑编译契约与 GDB 测试。

### 7.2 用户安装目标

拟定体验（未发布，不能把以下命令当作当前可运行的安装教程）：

```text
cargo add dbgvis --optional --no-default-features --features derive
cargo install cargo-dbgvis --locked
cargo dbgvis setup --project . --debugger gdb
cargo dbgvis doctor
```

依赖添加后，按 7.4 节配置项目 `visualize` feature、业务侧条件声明与 enable；setup 生成项目级调试配置和版本化脚本路径，调试构建显式启用该 feature。setup 不改业务源码；必要启用步骤由 doctor 指出，并在模板中提供示例。命令内部优先使用本包内置资源，不在用户机器运行时从远端任意下载脚本。

GDB：把脚本打包/嵌入逻辑移进发布包自身，消费项目不复制 build.rs/Python。验证该 crate 作为依赖时自动加载资源确实进入最终二进制；若依赖侧属性未保留，使用生成的根锚点补足。safe-path 只信任选定项目/二进制，不设为 `*`。

LLDB / CodeLLDB 暂不实现。后续重新立项时须解决独立加载和类型关联问题，不能认为 GDB 的嵌入脚本会自动在 LLDB 生效。[Rust debugger 属性](https://doc.rust-lang.org/reference/attributes/debugger.html)

所有配置变更必须项目级、幂等、可卸载；已有 launch.json 按配置项合并，不覆盖无关配置或用户的注释。写入前给出变更预览，保留可恢复备份；默认不修改全局 `.gdbinit` / `.lldbinit`。项目搬家或 bundle 被移除时，doctor 明确定位并提供重新 setup 的操作。

后续 doctor 至少检查：crate/脚本协议兼容、启用 feature、注册表/anchor 与调试信息、GDB safe-path、目标调用/超时支持，以及 release/strip 的限制。不为诊断而自动执行用户 formatter。当前通过 `dbgvis types/config/status` 和构建依赖图进行人工核查，尚无 doctor CLI。

### 7.3 分发验收而非只验证源码仓库

后续使用 `cargo package` 产物或等价离线安装包，在无仓库源文件的临时目录完成 setup → build → GDB 展示 → uninstall。完整发布演练包含空格路径、依赖重命名、重复 setup、已有配置、升级/协议不匹配和禁用 feature。当前临时消费项目与搬移二进制测试只覆盖其中一部分，不等价于发布演练。

这轮要求完成可分发产物与本地发布演练；实际 crates.io 发布、远端推送、平台商店扩展发布需要另行授权，不由“实施计划”隐含授权。

### 7.4 编译开关、运行开销与跨 crate feature 传递

区分三层开销，不把运行时关闭等同于没有编译开销或二进制占用：

| 环节 | 开销 | 关闭方式 |
| --- | --- | --- |
| derive 展开及实现生成 | 编译时间、可能的代码/调试信息体积 | cfg_attr + 可选依赖；未启用时不展开宏 |
| 注册初始化、dispatcher、静态缓冲区 | 启动工作及产物/内存占用 | 同一 feature 条件编译根注册与 enable |
| 递归格式化 | 调试请求时的目标执行 | 默认 manual/native；不开启自动调用、不发显式打印 |

derive 只生成格式化实现，不给正常业务对象的构造、修改、访问插入监控逻辑。开启构建支持但尚未请求格式化时，不遍历业务对象；enable 的初始化开销仍需单独测量。manual 下显式打印依然执行目标代码，不能宣称它是完全禁止执行的开关。

a/b/c 各自声明默认关闭的 `visualize` feature，连接可选 dbgvis 依赖；应用将同名 feature 显式传递到这些依赖。推荐配置示意：

```toml
# a/b/c 各自的 Cargo.toml；dbgvis 是带 derive 能力的可选依赖。
[features]
default = []
visualize = ["dep:dbgvis"]
```

```toml
# 应用 Cargo.toml；a/b/c 为正常依赖，dbgvis 为可选依赖。
[features]
default = []
visualize = ["dep:dbgvis", "a/visualize", "b/visualize", "c/visualize"]
```

对象声明及所有辅助属性一起受条件控制，不能只关 derive、留下无法识别的 dbgvis 字段属性：

```rust
#[cfg_attr(feature = "visualize", derive(dbgvis::Visualize))]
pub struct State {
    #[cfg_attr(feature = "visualize", dbgvis(via = "debug"))]
    value: ExternalValue,
}

fn main() {
    #[cfg(feature = "visualize")]
    dbgvis::enable!();
    // 正常业务代码；也可用 cfg_attr 条件添加 dbgvis::main。
}
```

以上开关模式用于独立临时消费项目和 a/b/c fixtures；仓库 demo 不使用这些 gate。cfg/cfg_attr 由 Rust 提供，开启时才应用 derive 及辅助属性。[Rust 条件编译](https://doc.rust-lang.org/reference/conditional-compilation.html#the-cfg_attr-attribute)

上述消费项目用 `cargo build --features visualize` 启用，release 本身不关闭 feature。显式登记示例用 `cargo build --example explicit` 或 `cargo run --example explicit`；Debug 自动登记示例 demo 必须通过 driver 构建，完整命令见 README。两者始终启用；原 src/main.rs 与根包 visualize feature 已删除。

Cargo feature 是叠加的：根包 `--no-default-features` 不能强制关闭其他依赖路径已经开启的 feature。各库要遵守默认关闭约定，doctor/CI 用实际依赖图核查开关传递；不设计“disable” feature 与“enable” feature 互相覆盖。[Cargo feature 合并规则](https://doc.rust-lang.org/cargo/reference/features.html#feature-unification)

关闭验收：在独立消费项目的生产构建图中，dbgvis/runtime/proc-macro 可选依赖不被引入；最终二进制无可视化注册表、dispatcher、专用缓冲区及初始化调用。若其他依赖启用 dbgvis，明确报告不能满足完全关闭，而不是保证根 feature 单独控制整个依赖图。CLI 安装工具单独存在不意味着目标程序链接它。

CI 同时测试 feature 开启/关闭、debug/release/LTO，并在开启路径运行 trait 能力与自动回退测试，避免关闭 feature 后隐藏编译错误。7.4 节之外的简化 API 示例省略条件属性，仅用于说明启用状态下的行为。

## 8. 分阶段实施与验收

依赖顺序：Q0 → Q1 → Q2 → Q3 → Q4 → Q5。先验证自动类型关联与泛型 trait 优先级，再扩展 API 和容器，不把关键不确定性留到最后。

### Q0：API 契约与类型关联验证

交付：最小 proc-macro 原型、typed anchor 原型、TypeId/注册 slot 模型、owned/borrowed 根类型路径；固定 facade 示例、自动 trait 优先级契约和 MSRV。

验收：

- GDB 能在不手填名称/别名的情况下将普通局部变量匹配到正确注册入口；发现阶段零目标调用。
- 覆盖 HashMap 默认 hasher、自定义 ZST hasher、重导出/别名、同名类型、同布局类型、借用字段；debug/release/LTO 检查锚点与函数保留。
- TypeId 留在 Rust 内，不以裸字节/哈希绕过验证；带生命周期入口没有偷偷添加 `'static` 或延长实际借用。
- 验证默认 Visualize > Debug > Display、显式 via 覆盖及 skip；覆盖只有各单一能力、多能力同时存在和三者均无。后者编译失败，Debug-only/Display-only 普通字段成功。
- 验证具体 External 字段、Wrapper<T>、Vec<External>、HashMap<String, External>、跨 crate 泛型包装；使用已批准的 nightly specialization，不能退化为强制 via 或要求同时实现多个 trait。
- 记录成功路径和明确失败诊断；若关键关联不可靠，先修正设计，不宣称可以一行接入。

### Q1：递归引擎与基础类型

交付：Visualize、统一能力选择机制、Formatter builders、标准容器泛型实现、自动/显式 Debug/Display 文本叶子；无需调试器即可运行的字符串断言测试。

验收：

- HashMap<String, Vec<Option<Record>>> 及不同 K/V/S 递归输出逻辑内容；不依赖 Debug 完成自定义递归。
- 同一容器分别装入 Visualize-only、Debug-only、Display-only 类型，普通声明均可输出；具备 Visualize 和 Debug 且两者结果不同的元素必须优先 Visualize。第三方整容器若选中 Debug，则明确测试其整值委托边界。
- UTF-8/NUL、容量边界、深度/节点限制、共享对象、循环、ZST 元素/策略、借用 str/slice 均正确。
- 预算耗尽后不继续迭代；受控实现不通过无界中间分配生成整棵树。单独标明无法约束的用户 Debug/Display 或手写 Visualize 行为。

### Q2：完整宏与组合注册、v2 文本协议

交付：derive 与字段 via、模块注册、main/enable、跨 crate trait 递归组合和 typed Registration；新增协议 v2 文档。多个根集合的组合另行验证，不作为递归机制。

验收：

- 泛型/借用/enum/字段策略、依赖重命名可编译；非法属性、显式 trait 缺失、同一条目重复 default 属性产生编译错误。自动能力缺失需代码生成；跨根集合按具体类型身份合并或拒绝冲突，不声称 proc-macro 具有全程序编译期查重。
- 普通字段三种能力均不可用、via Debug 缺少 Debug、via Display 缺少 Display、根显式声明能力不满足，均有编译失败测试；涵盖容器和泛型实例。External 字段只有 Debug/Display 时无需 via、也无需自己的根注册即可成功输出。
- skip 字段不要求格式化 trait；PhantomData/ZST 策略及无关泛型参数不被附加多余约束。带借用字段的有效泛型实例必须能编译。
- 独立 fixture workspace 含 a、b、c 与 main：库只 derive、不手工登记、不 enable，非泛型根由 linkme 汇集；泛型 a::Record 不登记也能嵌套递归。main 的 AppState 自动登记。至少一组库类型无 Debug，证明没有绕行 Debug。
- 同一 T 同时实现 Visualize 和 Debug 且输出不同：普通字段走 Visualize，via Debug 字段走 Debug；整个根选择 Debug 时不应用 Visualize 字段属性。
- 统一 runtime trait 的跨 crate 组合通过；不兼容 trait 版本的 fixture 无本版本可用能力时编译失败，有 Debug 时只能按回退规则输出 Debug，不计作 Visualize 互操作。两个根集合可以组合，同一 T 的默认视图冲突不能静默覆盖。
- 对象类型与函数指针不能混搭；enable 前后、禁用 feature、release/LTO 都有测试。
- a/b/c 和应用的 visualize feature 同步传递；关闭后条件 derive、辅助属性、根注册和 enable 全部消失，业务类型本身仍能正常编译。

### Q3：GDB 文本前端（核心已实现，继续扩充边界测试）

交付：v2 协议解码、默认视图选择、递归摘要、明确截断诊断、native 共存；无 v1 兼容层。

验收：

- GDB 文本与 Rust formatter 的结果一致；HashMap 展示键值，而不是 RawTable/控制字节/策略布局。
- 根值一次显式打印至多一次 dispatcher 调用；深层/大容器不存在 child count/page 往返。
- 自包含 demo 的 main 断点验证 AppState 递归、自动根及未登记根拒绝。a/b/c 的递归、自动登记数量、未引用类型的符号保留由临时消费项目的 debug/LTO 构建与执行验证；不将它们冒充当前 GDB demo 的覆盖。
- native/manual 加载零调用；automatic 明确启用。更换二进制、刷新、同停顿写值不复用旧文本。
- 原有故障测试、core dump 回退、无地址/优化掉的值、已有 formatter 共存继续通过。
- 被选中的高优先级实现发生错误、panic、截断或超时，低优先级实现调用计数保持为零；自动能力回退不产生失败重试。

## 9. 迁移与完成定义

按用户批准删除 v1，只提供 v2。当前入口为非泛型自动登记的 derive、register 属性、register_type! 及无参数 enable/main。迁移时删去自有非泛型类型的重复集中登记；第三方/泛型条目移至 register_type! 或 register alias；如需显式模式，用 no_register + register。旧二进制使用自身嵌入的旧脚本；本次只改注册来源，不改变 v2 wire 布局。

`Children<T>`、`dbgvis page` 和 structured children 删除。新格式化路径不经由旧子元素描述符绕行。旧[验收记录](验收记录.md)仅是历史证据，不能证明当前实现通过；当前核心与后续待办在[第二阶段验收记录](第二阶段验收记录.md)分别列出。

第二阶段完成必须同时满足：

1. 自有非泛型类型 derive 后自动登记，enable 后即可递归显示；泛型具体根只需一条声明。
2. 有 Debug/Display 的第三方类型可一条注册声明接入。
3. 普通字段自动按 Visualize > Debug > Display 选择，具体字段、泛型容器及跨 crate 一致；三者均不可用才编译失败。显式 via/根能力声明仍严格检查，调用失败不重试其他 trait。
4. HashMap、泛型嵌套和复杂 ZST 抽象无需 Python 私有布局适配；用户不写分页。
5. 消费项目从安装包接入，不复制本仓库构建脚本和 Python 文件。
6. TypeId/anchor 匹配、借用生命周期、预算和失败回退均有实际测试，不能只完成宏语法演示。
7. a、b、c 的非泛型 derive 根自动收集，main 无需汇总；泛型嵌套无需根登记，已有 Visualize 不被低优先级 Debug 遮蔽。
8. 默认关闭开关贯穿 a/b/c 和应用，生产构建无可视化初始化、dispatcher、注册表和预留缓冲区；开启但未请求格式化时不遍历业务对象。

范围为 Linux x86_64 本地 live process、GDB、nightly specialization。LLDB/CodeLLDB、Windows/Natvis、macOS、跨架构、远程、多动态库及纯内存 core 可视化后续独立立项。第三方 adapter、remote/getter 和 Serde bridge 不在本轮范围内。TypeId 与 proc-macro 不会自动提供缺失机器码、恢复被优化掉的值、绕过私有访问或保证任意目标函数安全。
