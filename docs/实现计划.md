# debugger_visualizer 工程化实现计划

状态：原始设计与验收计划；P0–P5 的落地情况、实际 API 与本地验证证据见[验收记录](验收记录.md)、[使用指南](使用指南.md)和[协议 v1](协议-v1.md)。下文保留最初拟定方案，示意语法和实际接口的差异以这些文档为准。

## 1. 目标与术语

将当前按类型手写 FFI 函数和 Python 映射表的 POC，演进为可注册类型、可选择输出模式、可展开容器的调试可视化组件。

本文将“原生格式化”定义为**沿用 GDB / LLDB 已有的显示方式，包括工具链提供的 pretty-printer**，配置名为 `native`。调用 Rust 类型自身实现的两种模式分别命名为 `debug` 和 `display`，避免“原生”同时指调试器显示和 Rust trait 实现。

核心目标：

1. 用户可选择 `native`、`debug`、`display` 摘要输出模式。
2. `debug` / `display` 直接写入可调整容量的有界缓冲区，复用现有 trait 实现。
3. 提供统一调用入口、可发现的类型注册表和具体类型的函数指针。
4. 容器支持按需、分页展开，子元素保留类型和后续展开能力。
5. 同一份 Rust 注册声明服务于 GDB 和 LLDB，减少手工映射。
6. 每个阶段都有可独立演示、验证的结果。

首版范围为 Linux x86_64、本地 live process、GDB 和 LLDB；CodeLLDB 验证其集成行为。跨架构、远程调试和其他操作系统作为后续兼容阶段，不预先承诺。Core dump 支持 `native` 及不需要目标执行的显示路径。

## 2. 当前基础与需要先修复的问题

当前调用链为 Python 获取变量地址 → Rust C ABI 包装函数 → `format!` / `write!` → `CString` → Python 读取 → Rust 释放。

已有可复用部分：

- `src/main.rs` 中 `Bytes` 和 `IndexMap<i32, &str>` 的原生 `Debug` 调用。
- `src/printer.py` 的 GDB pretty-printer 接入。
- `src/lldb_linter.py` 的 LLDB summary 接入。
- `.vscode/launch.json` 的 CodeLLDB 脚本加载入口。

需要处理的已知问题：

- GDB 的 `IndexMap` 映射使用了不存在的 `debug_print_indexmap`。
- 注册了尚无实现的 regex 函数，容易让能力表与实际实现脱节。
- LLDB 注册 category 后没有显式启用；重复导入和注册范围也需要管理。
- Python 异常路径可能跳过 CString 释放，LLDB 的释放失败被忽略。
- Rust 通过 `unwrap()` 处理格式化及 CString 构造错误，不适合作为通用接口。
- LLDB 读取限制为 2048 字节，但 Rust 仍先生成完整字符串，不是真正的有界输出。
- 两套脚本硬编码调试器类型名称；`i32` / `int` 等差异需要适配。
- `#[used]` 不能单独保证最终链接产物保留入口和注册表。
- `p` 可能生成临时值，但不能把“所有 p 都没有地址”作为固定规则；应检查每个值的实际存储位置。

## 3. 用户配置与输出行为

### 3.1 摘要、执行权限与展开分别配置

以下为拟定配置，具体命令语法在适配层阶段固定：

| 配置 | 取值 / 建议初始值 | 语义 |
| --- | --- | --- |
| `summary.mode` | `native` / `debug` / `display`；默认 `native` | 摘要显示方式 |
| `summary.alternate` | 默认 `false` | `debug` 使用 `{:#?}`；`display` 使用 `{:#}` |
| `summary.buffer_bytes` | 默认 4096 | 本次格式化最多写入的 UTF-8 字节数 |
| `execution` | `manual` / `automatic`；默认 `manual` | 目标代码仅由显式命令执行，或允许变量视图自动执行 |
| `children.mode` | `native` / `structured`；默认 `native` | 使用原有子节点，或使用注册的元素枚举器 |
| `children.page_size` | 默认 64 | 一页逻辑元素数量；map 的一对键值算一个元素 |
| `children.max_items` | 默认 1024 | 本次停顿允许展示的逻辑元素上限 |
| `execution.timeout_ms` | 默认 200 | 请求超时目标值，仅在后端支持时生效 |

支持全局默认值和类型级覆盖；显式打印命令可以临时覆盖模式、容量和 alternate，不修改长期配置。优先级：命令参数 > 类型配置 > 全局配置。

拟定使用示例：

```text
可视化配置：默认 native
可视化配置：MyType 使用 display，缓冲区 8192 字节，允许自动调用
可视化配置：IndexMap 使用 debug 摘要和 structured children
显式打印：以 debug 模式打印 map，缓冲区 16384 字节
```

`execution=manual` 时，变量视图沿用 native；显式命令才执行已选择的 Rust 格式化器。配置和帮助信息必须解释这一点。选择自动调用后，用户无需逐次确认。

### 3.2 模式与回退规则

| 请求 | 实际行为 |
| --- | --- |
| `native` | 本组件不执行目标函数，交回已有格式化器 |
| `debug` 且已注册该能力 | 调用具体类型的 `Debug` 适配函数 |
| `display` 且已注册该能力 | 调用具体类型的 `Display` 适配函数 |
| 所选 trait 未注册 | 自动视图回退 native；显式命令报告能力缺失 |
| 无有效目标地址、进程不可执行或 ABI 不兼容 | 回退 native，并提供可查询原因 |
| 缓冲区不足 | 返回已写入的合法 UTF-8 前缀，并在 UI 标识“已截断” |
| 目标调用失败 | 不返回旧缓存冒充新结果；回退 native，保留诊断信息 |

不将 `display` 静默改成 `debug`。`Bytes`、`IndexMap` 首先注册 `Debug`；用自定义示例结构体验证 `Display`，不假设第三方容器实现了 `Display`。

原生回退必须避免再次进入本组件：GDB 在 lookup 层决定不接管；LLDB 通过独立 category、注册启停及 non-synthetic 原始值路径处理。对于“本组件已接管后发生失败”的情形，验证原有 formatter 能否恢复；不能恢复时显示原始字段和明确原因，不能声称已恢复原生 formatter。

## 4. 总体架构

```text
用户配置 / 显式命令
        ↓
GDB 适配层 / LLDB 适配层
        ↓
共享协议、类型匹配、缓存与错误处理
        ↓
读取版本化注册表 → 判断能力和目标状态
        ↓
统一 C ABI 入口
        ↓
具体类型适配函数
   ├─ Debug → 有界 writer
   ├─ Display → 有界 writer
   └─ children → 分页子元素描述符
```

原生路径在适配层直接结束，不经过本组件的统一执行入口。第三方既有 formatter 的行为由其自身定义。

建议最终目录结构：

```text
crates/visualizer-runtime/       注册表、协议、dispatcher、有界 writer
crates/visualizer-adapters/      Bytes、IndexMap 等容器适配
debugger/common/                协议解码、配置、类型匹配、缓存
debugger/gdb/                   GDB pretty-printer、命令、children
debugger/lldb/                  LLDB summary、synthetic children、命令
examples/                      可断点验证的示例程序
tests/integration/             GDB、LLDB 批量验证
docs/                          使用指南、协议、支持矩阵
```

先实现声明式注册宏；只有确有收益时，再新增 proc-macro crate。迁移到 workspace 时保留一个行为清晰的演示入口。

## 5. 统一入口与 ABI

### 5.1 协议形态

首版采用“一个执行入口 + 一个导出的模块描述符”。示意签名：

```rust
// 设计示意，字段布局与错误码需在第一阶段固定。
unsafe extern "C" fn dbgvis_dispatch_v1(request_addr: usize) -> u32;
// 同时导出 DBG_VIS_MODULE_V1，供调试器直接读取。
```

模块描述符包含：ABI 版本、结构大小、目标指针宽度、类型表地址和数量、请求邮箱地址、输出区地址及容量、dispatcher 定位信息。静态元数据发现不要求先执行 Rust 函数。

请求包括：结构大小、请求序号、操作码、类型条目 ID、对象地址、模式、容量、分页参数；响应写入模块拥有的固定响应区。入口只返回整数状态码，避免跨调试器处理复杂返回结构体。

首版操作码：

- `FORMAT`：格式化摘要。
- `CHILD_COUNT`：查询逻辑子元素数量和容器形态。
- `CHILD_PAGE`：读取一页子元素描述符。

协议结构使用 `#[repr(C)]`、明确的整数和长度字段，不暴露 Rust `String`、`Vec`、trait object、`Result` 或 enum 的内部布局。Python 根据目标端信息解码，不使用宿主机的指针宽度和字节序作为默认假设。

入口校验请求版本、结构大小、操作码、类型 ID、能力位、容量和整数运算溢出。首版只接受模块声明的请求邮箱地址，以减少任意请求指针的暴露；对象地址仍需满足类型、对齐和存活约束。

错误码至少包含：`OK`、`TRUNCATED`、`UNSUPPORTED`、`INVALID_REQUEST`、`ABI_MISMATCH`、`BUSY`、`FORMAT_ERROR`、`PANIC`。调试器另行记录无法执行、内存不可读、超时和无地址等后端错误，不伪装成 Rust 返回值。

### 5.2 类型注册与函数指针

每个类型条目包含：

- 模块内类型 ID、显示名称、大小和对齐要求。
- GDB / LLDB 名称匹配信息和明确的别名。
- 能力位：`DEBUG`、`DISPLAY`、`CHILDREN`。
- 可选的具体类型 `debug_fn`、`display_fn`、`children_count_fn`、`children_page_fn`。
- 容器形态和适配器版本（普通结构、序列、map）。

函数指针由 Rust dispatcher 调用，Python 不直接调用各类型内部函数。模块内部可使用 Rust 调用约定，但不能将其作为跨模块、跨版本插件 ABI。

注册宏的拟定用法：

```rust
// 仅为 API 设计草案，不是当前已有宏。
register_visualizers! {
    bytes::Bytes => { debug, children: BytesElements },
    indexmap::IndexMap<i32, &str> => { debug, children: IndexMapEntries },
    MyType => { debug, display },
}
```

宏生成单态化适配函数和静态条目，编译器检查声明的 trait 能力。首版由可执行程序集中列举具体类型，不尝试自动搜集所有依赖中的 trait 实现。泛型按具体实例注册；不能只注册一个抽象 `IndexMap<K, V>` 就覆盖所有实例。

带引用的类型必须明确生命周期擦除策略：只在本次调用内借用对象，不因登记类型而要求实际数据为 `'static`，也不通过 `Any` 强加 `'static` 限制。示例增加非静态字符串引用，验证该约束。

类型匹配按“模块身份 + 完整类型匹配 + 大小/对齐辅助核对”进行。ID 不使用跨构建稳定性未定义的 `TypeId`，也不只依赖名称哈希。大小/对齐和名称只能降低误匹配，不能证明任意指针有效。`i32` / `int` 等规范化要按目标信息处理，禁止盲目字符串替换。名称有歧义时拒绝执行。

首版只支持单一根注册表；多动态库的发现、同名符号消歧和模块卸载安排在后续阶段。

### 5.3 符号保留和脚本分发

- 演示程序通过可达的初始化/锚点代码引用模块描述符和 dispatcher。
- 将最终二进制符号检查列为验收项，覆盖 debug、release 和 LTO。
- 不把 `#[used]` 等同于链接器级保留保证；必要时为支持的平台提供显式链接保留配置。
- 入口与注册表布局带版本号，脚本遇到不兼容版本应回退。
- GDB 的嵌入脚本优先产出可独立加载的打包文件，解决嵌入脚本导入共享 Python 模块的路径问题。
- LLDB 提供显式加载入口；CodeLLDB 配置使用同一套产物。
- 记录 GDB auto-load safe-path 配置，禁止以全局关闭加载保护作为默认安装步骤。

## 6. 有界格式化缓冲区

### 6.1 内存与所有权

首版在 runtime 内预留请求、响应和输出区，默认输出区上限建议为 64 KiB。用户的 `summary.buffer_bytes` 可在 1 到该上限之间调整；需要更大上限时通过编译配置改变预留容量，并在模块描述符中公布。超出上限明确报错，不静默扩大内存。

调试器向固定请求邮箱写入参数，执行统一入口，再按响应长度读取模块拥有的输出区。这样首版不依赖 GDB 侧目标内存分配，也不需要每次返回 CString 后再释放。

缓冲区只在调试专用 feature 启用时编入程序。一个模块同时只处理一个请求，采用不等待的重入保护；遇到占用立即返回 `BUSY`。Python 同时维护会话级调用保护，避免 formatter 递归触发新调用。

响应携带请求序号，调试器校验其与请求一致。输出在下一次调用前必须复制到调试器内存；所有会改变输出区的操作共享同一串行通道。序号用于检测过期响应，不替代串行化。

### 6.2 Writer 语义

直接实现 `std::fmt::Write`，由 `write!` 将内容写入预留区：

- 不先 `format!` 到无界 String 再截断。
- 以字节计算容量，但只保存合法 UTF-8 前缀；支持内嵌 NUL。
- 响应返回 `written_len` 和截断状态，Python 读取精确长度，不调用 C 字符串读取接口。
- 首次无法容纳内容时设置截断标记并返回 `fmt::Error`；后续写入保持拒绝状态。
- 如果没有截断却收到 `fmt::Error`，返回 `FORMAT_ERROR`，与容量不足区分。
- 不保证返回完整输出所需长度，因为得到该长度可能必须执行完整格式化。
- 不自动扩大容量重试；用户显式请求更大容量时才重新执行格式化。

缓冲区约束的是桥接层存储，不是任意用户 `fmt` 的计算量或内部内存分配。用户实现可能忽略写入错误、继续循环，甚至不写输出而无限运行；超时仍需调试器配合。

### 6.3 调用失败边界

在 `panic=unwind` 构建中，于 Rust 内部、C ABI 边界以内捕获可展开的 panic，转换成 `PANIC`。不能保证无副作用，panic hook 仍可能执行；不临时替换全局 panic hook。对 `panic=abort`、非法访存及进程崩溃不能承诺恢复。

不等待内部互斥锁、不进行自动重试。目标调用中断后先检查进程和调用帧状态；无法确认 dispatcher 已退出时，将本会话目标调用标记为不可用，不能强行清空忙标记后继续重入。

## 7. 容器展开

### 7.1 子元素协议

摘要与展开独立，允许 `debug` 摘要配合 `native` children，也允许 `native` 摘要配合显式配置的 `structured` children。

`CHILD_COUNT` 返回逻辑元素总数；`CHILD_PAGE(start, count)` 返回固定上限的一页描述符，且校验索引及数量溢出。不一次复制整个容器，不从 Debug 字符串反向解析元素。

每个描述符至少包含名称或索引、值的类型引用、目标地址或内联标量、值类别。map 的一条逻辑元素记录包含 key 和 value 两个描述符。名称和描述符存储也有独立的固定容量，不能通过大量标签绕过摘要缓冲区限制。

子元素不一定注册了 Debug / Display；没有注册格式化能力时，仍可通过调试信息还原有类型的值并使用 native。找不到可信类型信息时返回不可展开的标量/诊断，不进行猜测性指针转换。

稳定存储的元素可返回借用地址；临时计算值必须复制到有界响应区，并由脚本立即拷贝，禁止返回临时局部变量地址。首版复杂子值只支持在原对象中有稳定存储位置的类型；`str`、slice 等胖指针通过明确描述符或实际引用槽处理，不当成一个普通地址。

### 7.2 首批容器

| 类型 | 展开方式 | 验证重点 |
| --- | --- | --- |
| `Bytes` | 使用公开访问接口按索引返回 u8 元素 | 空值、切片后的偏移、共享底层存储 |
| `IndexMap<i32, &str>` | 按插入顺序分页返回 key/value | 增删后的顺序、非静态 &str、分页边界 |
| 自定义结构体 | 宏或适配器登记字段名称和借用地址 | 嵌套值、缺失 trait 的字段、循环引用 |

Rust 适配器优先通过容器公开接口获取长度和元素位置，避免 Python 硬编码第三方私有布局。这也意味着 `structured` 查询会执行目标代码，受同一 execution 策略约束。

纯读内存的容器适配器可作为后续独立能力：它适合 core dump，但需要单独维护布局版本，不能宣称现有 Rust 枚举器无需目标执行。

### 7.3 调试器展示与缓存

- GDB：实现 `children()`；序列使用 array 形态，map 使用符合 GDB 约定的键值交替子项和 map hint。
- LLDB：实现 synthetic children provider；map 可显示 `[i]` 节点，下挂 `key` / `value`。不能为展示方便伪造不符合实际布局的连续键值对象。
- 首版 LLDB 如果不能可靠表达一对地址分离的键值，先使用 `[i].key` / `[i].value` 平铺有类型节点，并在使用文档说明。
- 超过 `max_items` 时展示明确的省略提示；提供修改上限或显式页查询命令。
- 缓存 key 包含进程、模块、停顿代次、对象地址、类型、配置和页号；同一次停顿内也要响应 debugger 写值、表达式执行和可检测的目标调用而失效。
- 恢复运行、单步、模块加载/卸载、类型配置修改后清空相关缓存；LLDB 使用 stop ID，GDB 维护相应事件代次。
- 本组件每次目标执行至少使其他对象的缓存失效；无法检测外部执行或写入时不声称缓存可靠，提供显式刷新并采用保守缓存策略。
- 自身 formatter 的重入保护与对象图循环检测分开处理；按访问路径限制深度，避免全局去重误伤共享子对象。

## 8. 分阶段实施与验收

依赖顺序：P0 → P1 → P2 → P3 → P4 → P5。跨平台扩展在 P5 之后。

### P0：修复 POC，建立运行基线

交付：修复现有映射与加载问题；准备固定断点示例；记录调试器和工具链版本。若这一阶段继续保留 CString 协议，补齐释放及错误路径，待 P1/P3 完成后移除旧协议。

验收：GDB、裸 LLDB、CodeLLDB 可显示 Bytes 和 IndexMap；连续停在插入前后能看到值变化；未实现的 regex 能力不再被误注册。

### P1：实现 runtime 协议与有界格式化

交付：版本化描述符、统一入口、邮箱和输出区、状态码、有界 writer；先手工登记两个具体类型和一个 Display 示例，验证协议可用。

验收：

- `Debug` / `Display` 正确输出，桥接层不依赖 CString 分配和释放。
- 验证精确容量、空输出、多字节字符、内嵌 NUL、截断、fmt 错误和可捕获 panic。
- 请求错误、过大容量、能力缺失和重入返回明确状态；测试使用有效分配对象，不通过对随机地址解引用测试“安全性”。
- 为受控的无分配 fmt 实现验证桥接层无堆分配，不将结论推广至任意 fmt。

### P2：生成类型注册表，稳定符号发现

交付：声明式注册宏、单态化函数指针、显式类型别名、集中注册入口及符号保留策略。

验收：新增一个类型只需实现 trait 并登记，不再新增具名 FFI 导出和 Python 字典项；声明不存在的 trait 能力编译失败；同形不同类型不误匹配；debug/release/LTO 最终二进制均可发现注册表和入口。

### P3：统一两套 debugger 前端及配置

交付：共享协议层；native/debug/display 模式；容量、类型覆盖、显式打印和自动调用配置；GDB 嵌入打包脚本和 LLDB 安装入口。

验收：

- native 路径不由本组件发起目标调用；有现有 formatter 时不被本组件遮蔽。
- manual 下仅显式命令执行；automatic 下变量视图按配置输出。
- 两个调试器的有效文本和截断状态一致；容量和模式修改立即生效。
- GDB auto-load、LLDB 重复导入和 CodeLLDB 加载有可重复步骤。
- 无地址值、ABI 不匹配、不可执行进程正确回退；临时值不被冒充为有效对象地址。
- 超时能力被探测；不支持可中断超时的后端明确提示限制，默认不自动执行。

P3 完成即形成首个可用版本：注册类型后按模式输出摘要。

### P4：实现分页容器展开

交付：子元素协议、Bytes / IndexMap 适配、GDB children、LLDB synthetic children、分页缓存与刷新。

验收：

- 在两种调试器中展开 Bytes 和 IndexMap，子元素具有正确类型和值。
- 摘要模式切换不破坏展开；选择 native children 可恢复已有树形显示。
- 大容器仅请求用户展开所需的页；一次返回量不超过配置限制。
- map 插入、删除、容器恢复执行后不复用旧元素地址。
- 验证非静态字符串引用、空容器、嵌套对象和引用循环。
- GDB 与 LLDB 的树形外观可以不同，但元素顺序、类型、数量及分页语义一致。

### P5：故障处理、发布文档与持续集成

交付：受控失败场景、支持矩阵、安装步骤、注册指南、协议说明、性能记录和 CI。

验收：

- 独立子进程覆盖受控 panic、调用超时、格式化递归和目标退出；测试本身由外部超时监管，避免 CI 挂死。
- `panic=abort` 验证明确为目标进程退出，不能计作可恢复错误。
- 在同一会话多次运行、重新加载及更换二进制时，不残留过期注册和缓存。
- Core dump 上 native 可用，主动格式化明确不可用，不执行目标调用。
- 记录短摘要、大量变量、分页大容器的延迟和调用次数；先测基线再确定性能门槛。
- 文档明确有界存储不等于纯函数、任意断点安全或严格执行时限。

P4/P5 完成后发布首个含结构化容器视图的版本。

## 9. 后续扩展及明确边界

后续可考虑：proc-macro 自动登记自定义结构体字段；跨 crate 显式组合注册表；多个动态库；远程及跨架构调试；容器纯内存适配；width/precision 等更多格式选项。

以下不作为首版承诺：

- 自动发现任意类型的 Debug / Display 实现，或调试时生成缺失的泛型机器码。
- 在 Python 中直接构造 Rust Formatter 或调用不稳定的 trait ABI。
- 自动判断任意用户 fmt 是否纯、无锁或无分配。
- 在无效地址、对象更新中间态、进程损坏或 panic=abort 后保证恢复。
- 将原始对象字节复制到临时空间，就认为能安全调用该对象的方法。
- 把超时、中断或恢复寄存器视作撤销目标调用的所有副作用。

首版重点是把当前已验证的调用方式做成可选择、可注册、可诊断的组件；输出文本和结构化展开分别演进。

## 10. 设计依据

- [Rust debugger_visualizer 属性](https://doc.rust-lang.org/reference/attributes/debugger.html)：嵌入脚本、Natvis 及 GDB 加载机制。
- [Rust Display](https://doc.rust-lang.org/std/fmt/trait.Display.html) 与 [Formatter](https://doc.rust-lang.org/std/fmt/struct.Formatter.html)：复用格式化实现的接口边界。
- [Rust used 属性](https://doc.rust-lang.org/reference/abi.html#the-used-attribute)：区分编译产物保留和最终链接保留。
- [GDB 调用目标程序函数](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Calling.html)：调用、中断、超时及目标状态影响。
- [LLDB 可视化扩展](https://lldb.llvm.org/use/variable.html)：summary 与 synthetic children 接入。

实现各阶段时，以实际采用的工具链版本验证这些接口；本文中的默认值、协议名称和目录结构均为拟定方案。
