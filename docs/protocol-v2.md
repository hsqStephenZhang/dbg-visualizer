# GDB Recursive Text Protocol v2

Current implementation: `crates/dbgvis-runtime/src/protocol.rs` and `crates/dbgvis-runtime/gdb.py`. Only 64-bit little-endian Linux local GDB is supported; it is not compatible with v1, and there is no child-node pagination protocol.

## Registration and type association

A non-generic `derive(Visualize)`, `#[dbgvis::register]`, or `dbgvis::register_type!(T)` generates, for each concrete root, a unique marker, a typed anchor, a `Registration<T>` factory, and a linkme entry. Within Rust, a separate marker TypeId and a concrete-type-identity TypeId are stored and are not transmitted over the wire. The former detects marker misuse; the latter decides whether formatters can be merged.

The application calls the no-argument `dbgvis::enable!()` once, which exports `DBG_VIS_MODULE_V2` and the unique `unsafe extern "C" fn dbgvis_dispatch_v2(request: usize) -> u64`. The runtime's `#[linkme::distributed_slice] pub static VIS_TYPES: [fn() -> Root]` collects the factory pointers in the current link artifact. enable calls the factories, sorts by type name, checks for duplicates, and freezes the v2 table; subsequent formatting does not extend it. Same-name registrations merge capabilities only when the concrete type identity matches and size/align match; if the identity differs, they are rejected even when the layout is the same. After sorting by type name and anchor name, the first default mode and the first entry for each capability are kept. A marker cannot be used for a different type.

GDB still reads the original v2 module header and Entry, does not parse linkme's linker section, and does not call the factories from Python. The factories only generate metadata, and there is no business fmt call during startup; linkme has no dynamic registration constructor, but enable's walk/allocation remains. A generic derive does not implicitly generate all monomorphized instances; an argument-free derive can disable automatic root registration with `no_register`.

`Registration<T>` invariantly binds T to the auto/Visualize/Debug/Display functions, and you cannot mix in another U's functions through the builder. The static anchor's empty `*const T` field is only for GDB to read DWARF and is never dereferenced.

A borrowed root uses the lifetime-erased identity generated by the macro: it replaces the registered type's free lifetimes with `'static` and takes the TypeId of that concrete type; the formatting entry point is still generated in a lifetime-generalized helper. The ordinary `Registration<T>::new` requires T: 'static; internally the macro associates the identity through the unsafe `new_lifetime_erased<Identity, Marker>`, whose contract requires that Identity and T may differ only in lifetimes. This identity is used only for merging within the current build and is not the runtime TypeId of the target object. You cannot extend an actual borrow to `'static` in a callback; an explicit fmt implementation that is only valid for `'static` lifetimes does not satisfy generalized registration.

The GDB discovery process only reads symbols/memory/debug info and does not execute target functions. The matching check verifies the owning main objfile, the full type name, and the type identity; when GDB Rust enum cross-compilation-unit type equivalence is insufficient, it additionally compares the full DWARF structure, including name, size/alignment, field offsets/types, array bounds, and the enum's active variant. A struct's dynamic type may lack trailing padding, so the range is restored by alignment during comparison. When there are multiple candidates or information is incomplete, it rejects.

The above are debugger anti-misuse measures, not an unconditional proof of Rust type identity/memory safety. It currently makes no promise about same-name different-crate-version cases or all optimization states; it does not directly treat a same-name same-size object as another T. The final caller still bears the requirements for the object's true type, liveness, and valid shared access.

## Module header

`Module` is `repr(C)`, 128 bytes, Python format `<8s15Q`. Every Q is a target little-endian 64-bit value:

| Offset | Field | Value/meaning |
| --- | --- | --- |
| 0 | magic | 8 bytes `DBGVIS02` |
| 8 | abi | 2 |
| 16 | size | 128 |
| 24 | pointer_width | 8 |
| 32 | endian | 1, little-endian |
| 40 | entry_size | 96 |
| 48 | request_size | 80 |
| 56 | response_size | 40 |
| 64 | ready | 1 when initialization is complete |
| 72 | entries | address of the immutable registry |
| 80 | count | 0–4096, empty table is legal |
| 88 | request | address of the unique request mailbox |
| 96 | response | address of the response mailbox |
| 104 | output | address of the output area |
| 112 | capacity | compiled output limit |
| 120 | dispatcher | C ABI function address |

ready/entries/count are atomics in Rust, and enable publishes ready. GDB reads only when the target is fully stopped; when uninitialized, it does not attempt to call enable.

## Registration entry

`Entry` is 96 bytes, Python `<12Q`:

| Offset | Field |
| --- | --- |
| 0 / 8 | Rust type_name text address / UTF-8 length |
| 16 / 24 | anchor symbol text address / length |
| 32 / 40 | size_of T / align_of T |
| 48 | capabilities bitset: AUTO=1, VISUALIZE=2, DEBUG=4, DISPLAY=8 |
| 56 | default mode (a single capability value) |
| 64 / 72 / 80 / 88 | auto / visualize / debug / display function pointers, may be 0 |

The functions inside the entry are **internal pointers of the Rust ABI**, which Python cannot call directly. Python only calls the C ABI dispatcher in the module header. Text is read by length and does not depend on NUL.

## Request and response

`Request` is 80 bytes, `<10Q`:

| Offset | Field | Constraint |
| --- | --- | --- |
| 0 / 8 | abi / size | 2 / 80 |
| 16 | sequence | new sequence number per request |
| 24 | slot | index in the current table |
| 32 | object | address of the actually-alive T, non-null and aligned |
| 40 | mode | 0 means the entry default; 1/2/4/8 means a registered capability |
| 48 | capacity | 1 to the compiled limit |
| 56 | alternate | 0 or 1 |
| 64 | max_depth | 1–128 |
| 72 | max_nodes | 1–1000000 |

Mode is not a fallback list: once selected, it executes only once. AUTO internally prioritizes Visualize > Debug > Display; a case where all three are missing in recursion should be rejected at the code-generation stage, not as a dynamic wire table-lookup failure.

The dispatcher only accepts the published mailbox address; you cannot pass an arbitrary Request pointer. On entry, a non-waiting CAS busy guard prevents reentrancy, and then it checks the parameters before constructing `&T`. The non-null/aligned check cannot prove that the object is still alive or satisfies its invariants.

`Response` is 40 bytes, `<5Q`: sequence, status, written, outcome, nodes. The return value is also status, and GDB must verify that the two are consistent, along with sequence and the output length. All normal error responses have written=0 and do not leak the previous output; an illegal mailbox or busy state is rejected outright before entry, with no promise to refresh the response mailbox, and GDB should then stop subsequent proactive calls.

| status | Name | Behavior |
| --- | --- | --- |
| 0 | OK | complete UTF-8 text |
| 1 | LIMITED | valid UTF-8 prefix plus the specific reason |
| 2 | UNSUPPORTED | mode not registered |
| 3 | INVALID | invalid parameter |
| 4 | ABI_MISMATCH | protocol incompatible |
| 5 | BUSY | does not wait; must not clear busy and force a continuation |
| 6 | FORMAT_ERROR | fmt::Error, not treated as a budget stop |
| 7 | PANIC | unwind caught on the inner side of the C ABI |
| 8 | NOT_READY | enable not yet complete |

outcome: 0 complete, 1 byte limit, 2 depth limit, 3 node limit, 4 cycle on the current path, 5 formatting error. A LIMITED prefix does not guarantee closed brackets or machine-parsability. GDB appends diagnostic markers outside the Rust output, without consuming the target capacity.

## Execution, caching, and safety

A single root request enters the dispatcher only once, and Rust writes all nested values into the same bounded area; there is no count/page/child-address request. The root registry may allocate; the normal framework recursive path uses a fixed-size access-path stack and the output area, and does not first create a complete string.

The output default limit is 65536, and `DBGVIS_BUFFER_BYTES` can be set to 1–16777216 at compile time; the request defaults are 4096, depth 32, nodes 4096. It does not retry automatically over the limit. The computation, allocation, and loops of direct Debug/Display and user-hand-written Visualize are not constrained by the framework's node budget.

GDB defaults to native/manual. automatic additionally requires local async-call timeout support; the 200ms default setting is rounded up to 1 second in GDB. It executes only when the target is fully stopped and function calls are allowed, and does not proactively release locks or undo the application's side effects.

The panic hook may run arbitrary user code. After an unwind panic is caught, if the payload's destructor panics again, the second payload is dropped (an intentional leak) to avoid passing through the C ABI. On abort, exit, timeout, signal, or an unconfirmable return, GDB marks poisoned, and refreshing/resetting the configuration does not clear it; recovery requires actually restarting the target process.

Metadata becomes invalid on continue, module load/cleanup, and exit; text is not cached across requests at all. On a core dump, no real storage, type ambiguity, or no execution permission, the native view is retained. Both the debugger script and the executed formatter require user trust.
