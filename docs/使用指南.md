# 使用指南：nightly / GDB v2

本文描述已实现的核心 API。仅支持 Linux x86_64 本地 live process、单个主可执行程序注册表。启用 dbgvis 需要 nightly specialization；不再提供 v1 API、分页或 LLDB/CodeLLDB 前端。安装 CLI 仍是[后续计划](实现计划.md)，尚未发布到 crates.io。

## 1. 自有类型与第三方类型

当前先用本地 path 依赖（替换实际路径）：

```toml
[features]
default = []
visualize = ["dep:dbgvis"]

[dependencies]
dbgvis = { path = "/absolute/path/dbg-visualizer/crates/dbgvis", optional = true, features = ["derive"] }
```

```rust
#[cfg_attr(feature = "visualize", derive(dbgvis::Visualize))]
struct State {
    entries: std::collections::HashMap<String, Vec<Option<u32>>>,
    address: std::net::SocketAddr,
    #[cfg_attr(feature = "visualize", dbgvis(skip))]
    cache: InternalCache,
}

#[cfg(feature = "visualize")]
#[dbgvis::visualizers]
mod visualizers {
    #[dbgvis(visualize)]
    type State = super::State;
    #[dbgvis(debug, display, default = "display")]
    type Address = std::net::SocketAddr;
}

fn main() {
    #[cfg(feature = "visualize")]
    dbgvis::enable!(visualizers);
    // 构造业务对象，在对象仍存活并可寻址的位置设置断点。
}
```

也可以用 `#[cfg_attr(feature = "visualize", dbgvis::main(registry = visualizers))]` 给 main 注入启用逻辑。与其他 main 属性宏的顺序没有通用兼容保证，冲突时在函数体中直接调用 enable。

derive 支持 struct、tuple struct、unit、enum、泛型、const generic 和借用字段，不要求类型同时实现 Debug。字段选择顺序固定为：显式 `via` > Visualize > Debug > Display。

- 第三方字段只有 Debug/Display 也能自动输出，不要求根注册，也不要求修改第三方库。
- 第三方容器本身没有 Visualize 时，委托它的整个 Debug/Display；不会从中自动切回元素的 Visualize。
- Vec、HashMap 等内置 Visualize 实现会对每个元素再次应用自动优先级。
- 三种能力都没有且未 skip：使用该具体实例的代码生成失败。请以 `cargo build`（含 release）验收，**`cargo check` 可能通过**。只是声明一个从未使用/注册的泛型 derive 不保证触发诊断。
- 已选定的实现失败后不重试低优先级实现。Debug/Display 不是纯函数保证，`dbg!` 也不是运行时可调用的 trait 方法；本组件复用 fmt 实现，不调用 dbg! 宏。

需要直接打印第三方根类型，只添加具体 type alias，例如：

```rust
#[dbgvis::visualizers]
mod third_party {
    type Bytes = bytes::Bytes; // 无模式属性：登记 auto
    type Ordered = indexmap::IndexMap<String, Vec<u32>>;
    #[dbgvis(debug)]
    type Borrowed<'a> = indexmap::IndexMap<&'a str, u32>;
}
```

注册泛型的具体实例，不支持 `type All<T> = Vec<T>` 形式的全类型族注册。生命周期可泛化；宏生成的静态空指针仅携带 DWARF 类型信息，不把真实借用变成 `'static`。只针对 `'static` 实现 Display 的借用类型不能声明为任意生命周期的显式 Display 根。

## 2. a/b/c 跨 crate 组合与开关

a/b/c 只需要各自 derive，私有字段由各自 crate 的生成代码访问。main 注册组合后的 AppState 即可；嵌套类型不必独立登记，库中也不调用 enable。

每个库默认关闭 `visualize`，启用时引入同一版本的 dbgvis。应用的 feature 显式传递：

```toml
[features]
default = []
visualize = ["dep:dbgvis", "a/visualize", "b/visualize", "c/visualize"]
```

项目开关同时包住 derive、字段 `dbgvis` 属性、注册模块和 enable。关闭时不展开宏、不链接 runtime/dispatcher、不预留输出区、不初始化注册表；业务字段布局不依赖该开关。

```sh
cargo build --features visualize
cargo build --release --no-default-features
```

release 不是关闭开关；`--release --features visualize` 仍启用。已实际验证根示例关闭功能可用 `cargo +stable build -p dbg-visualizer --no-default-features` 构建。Cargo feature 会叠加，其他依赖路径开启 dbgvis 时，根项目的 `--no-default-features` 不能替它强制关闭。

enable 每个可执行程序只能声明一次；可用 `dbgvis::enable!(first, second)` 组合多个根集合。同一类型的多个模式应放在同一条注册中；重复注册标记或规范类型名在 enable 时拒绝，不按链接顺序覆盖。此检查是初始化诊断，不是假称跨宏编译期全程序反射。

## 3. 字段控制与内置类型

| 属性 | 位置与语义 |
| --- | --- |
| `skip` | 字段；不读取、不输出、不添加格式化约束 |
| `rename = "..."` | 类型、enum 变体或命名字段；修改展示标签 |
| `via = "debug"` / `"display"` | 字段；严格要求对应 trait，不再自动选其他能力 |
| `transparent` | 单个有效字段的 struct；只输出该字段 |
| `bound = "T: SomeTrait"` | 类型；补充 where 条件 |

不提供第三方 remote derive、getter、自定义 adapter 或 Serde bridge。手写实现可使用 `Visualize::visualize(&self, &mut Formatter) -> dbgvis::Result`，通过 record/tuple/sequence/map builder 写入；应及时传播写入错误。

内置递归实现包括 slice、array、Vec、VecDeque、HashMap、BTreeMap、HashSet、BTreeSet、Option、Result、1–6 元组、引用、Box/Rc/Arc、PhantomData。HashMap 不要求 hasher 实现 Debug/Clone；PhantomData 不要求标记参数实现任何格式化 trait。其他类型按已有 Debug/Display 委托；不保证任意容器都具有深层 Visualize 语义。

## 4. GDB 加载与命令

runtime 自带构建脚本与 GDB Python，依赖侧 `debugger_visualizer` 将其嵌入最终产物。消费项目无需复制脚本或 build.rs。信任选定二进制即可：

```sh
rust-gdb -iex "add-auto-load-safe-path /absolute/path/to/binary" /absolute/path/to/binary
```

不设置全局 `safe-path *`。使用 rust-gdb 可同时保留工具链的标准库 formatter。自动加载 Python 本身需要信任，即使当前 execution 是 manual。

示例断在 checkpoint 后先 `up` 到 main 帧：

```text
dbgvis types
dbgvis print app
dbgvis print bytes
dbgvis print --mode display point
dbgvis print --mode native map
dbgvis print --buffer 32 --alternate app
dbgvis status
```

显式 print 在有效配置为 native 时改用该条目默认模式；`--mode native` 永远走原生显示，允许未注册类型。`--mode auto` 表示注册默认模式：无属性的注册会自动选择 Visualize > Debug > Display，有显式能力的注册只从声明过的能力中选择。请求未登记的 Debug/Display/Visualize 在目标调用前拒绝。

打开自动摘要：

```text
dbgvis config summary.mode auto
dbgvis config execution automatic
dbgvis config --type dbg_visualizer::Point summary.mode display
```

native children 保留，但不会生成新的逻辑子值树；无 `page` 命令。全局配置、类型配置、显式命令选项依次覆盖。类型名称取自 `dbgvis types`，包含空格时用引号。

| 配置 | 默认值 | 范围 |
| --- | --- | --- |
| `summary.mode` | native | native / auto / visualize / debug / display |
| `execution` | manual | manual / automatic |
| `summary.buffer_bytes` | 4096 | 1 到编译容量 |
| `summary.alternate` | false | true / false |
| `format.max_depth` | 32 | 1–128 |
| `format.max_nodes` | 4096 | 1–1000000 |
| `execution.timeout_ms` | 200 | GDB 超时向上取整到整秒，最少 1 秒 |

恢复配置用 `dbgvis reset`，刷新元数据用 `dbgvis refresh`。两者都不解除失败进程的 poisoned 状态。`status` 显示调用次数、累计时长及最近错误；一次根文本输出只调用 dispatcher 一次，不分页、不自动增大缓冲重试。

## 5. 预算、生命周期与故障边界

编译默认输出区为 65536 字节，可用 `DBGVIS_BUFFER_BYTES=131072 cargo build --features visualize` 调整到 1–16 MiB。每次请求在该区内写入 UTF-8，按长度传输，保留 NUL。超限返回合法前缀及 `<dbgvis: byte/depth/node limit>` 或 cycle 诊断，不保证括号闭合。此文本不是序列化存档。

框架的递归路径共享深度/节点/字节预算，并在迭代下一项前检查；循环检测仅针对当前访问路径，ZST 不单凭地址判重。不构造完整 DOM 或 String 再截断。用户 fmt/手写 Visualize 仍可计算、分配、忽略错误或无限循环；缓冲区不限制这些行为，Debug/Display 整值边界也不提供内部节点预算。

默认 manual/native 不自动执行目标代码；derive 不给普通业务访问插入监控。enable 一次初始化有注册表分配，静态输出区有内存占用；它们只受编译 feature 控制。

必须在 enable 之后、对象真正存活、可共享借用且可寻址时调用。对象正被修改、持有可变借用、未初始化或不满足 Rust 不变量时，暂停并不自动使调用安全。不能对优化掉的值复制字节后冒充真实对象。调试器类型元数据检查不是内存安全证明。

GDB 先比较主可执行文件所属的 typed anchor 类型；必要时核对完整 DWARF 结构（包括字段偏移/类型、enum 活动变体、对齐）。信息不足或多候选则拒绝，不按大小猜测。不能承诺处理所有同名不同 crate 版本、所有优化状态或生命周期敏感的 specialization。当前只验证文档列出的 nightly/GDB 版本，升级需重新验收。

automatic 要求 GDB 的异步调用超时可用；没有该能力则保留 native。显式调用在后端无超时能力时可能需要用户手动中断。不会主动获取应用 Mutex/RwLock；用户 fmt 自己阻塞仍有风险。

unwind panic 在 C ABI 内侧捕获，panic hook 仍会执行；fmt::Error 返回错误且不重试其他 trait。超时、abort、目标退出或无法确认返回时，将进程标为 poisoned，只能重启后恢复，不能清除 Rust busy 标志强行继续。超时/恢复寄存器不会撤销已发生的副作用。core dump 无法调用 Rust，只能沿用 native。

文本不跨请求缓存，同次停顿内修改值后下一次显式请求读取新结果。UI 自身持有的 varobj/显示缓存仍需前端重新请求。
