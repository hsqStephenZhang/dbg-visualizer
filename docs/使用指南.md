# 使用与注册指南

## 输出和执行策略

`native` 表示调试器已有视图；`debug` / `display` 分别调用已登记类型的 Rust 格式化实现。摘要与子项独立配置，运行目标代码的权限由 `execution` 控制。

默认加载后不接管变量显示。以下命令在 GDB、LLDB 和 CodeLLDB 调试控制台通用：

```text
dbgvis help
dbgvis config
dbgvis types
dbgvis print bytes
dbgvis print --mode display point
dbgvis print --mode display --alternate point
dbgvis print --buffer 32 map
dbgvis page --start 0 --count 2 map
dbgvis status
```

`print` 是显式执行命令：未指定模式且当前配置为 native 时，使用 Debug；`--mode native` 强制调用原有视图，允许打印未注册类型。`page` 是显式元素枚举命令，不受 automatic 开关限制。LLDB 命令参数接受可寻址的变量路径；任意 Rust 表达式、宏求值不在支持范围内。

断点位于示例 `checkpoint` 时，先通过 `up` 或 VS Code 调用栈选择 `main` 帧，才能访问 `map`、`bytes`、`point` 等局部变量。

打开变量窗口的 Rust 格式化和容器展开：

```text
dbgvis config summary.mode debug
dbgvis config execution automatic
dbgvis config children.mode structured
dbgvis config --type dbg_visualizer::Point summary.mode display
```

未登记的 trait 不会被猜测或替换：比如 Bytes 未注册 Display，自动摘要沿用原有视图，显式 `print --mode display bytes` 报 `UNSUPPORTED`。已注册的结构化子项仍可独立使用。

恢复默认值：

```text
dbgvis reset
```

## 配置

| 配置 | 默认值 | 范围与行为 |
| --- | --- | --- |
| `summary.mode` | `native` | `native`、`debug`、`display` |
| `summary.alternate` | `false` | `true` 对应 `{:#?}` / `{:#}` |
| `summary.buffer_bytes` | 4096 | 1 到二进制声明的输出区容量 |
| `execution` | `manual` | `manual` 仅显式命令执行；`automatic` 允许视图执行 |
| `children.mode` | `native` | `native` 或 `structured` |
| `children.page_size` | 64 | 1–64 个逻辑元素 |
| `children.max_items` | 1024 | 自动视图最多展示的逻辑元素数 |
| `execution.timeout_ms` | 200 | LLDB 使用微秒接口；GDB 向上取整到秒 |

优先级为命令选项 > 类型配置 > 全局配置。类型配置使用 `dbgvis types` 列出的规范名；名称中有空格时加引号。`dbgvis refresh` 通知适配层刷新视图；前端已有的 GDB varobj 需要前端重新请求变量。

文本区默认预留 65536 字节。需要改变编译上限时：

```sh
DBGVIS_BUFFER_BYTES=131072 cargo build
```

上限配置允许 1–16777216 字节；静态预留容量会影响二进制和进程内存占用。运行时超过该上限会报错，不自动扩容重试。部分输出始终是合法 UTF-8，截断标记由调试器追加，不计入目标端容量。嵌入 NUL 按长度传输，不提前结束文本。

格式化器可能继续计算、分配或忽略 writer 返回的错误；缓冲区只约束桥接层输出。GDB 仅在目标支持异步调用超时时启用 automatic；`maintenance set target-async off` 后自动回退，显式调用仍由用户负责中断。LLDB 禁止为格式化而尝试运行所有线程。

## 加载方式

### GDB

构建脚本把共享协议和 GDB 适配器打包为独立脚本，嵌入示例二进制的 `.debug_gdb_scripts`。自动加载只需要信任该二进制，移动二进制后不依赖仓库源文件：

```sh
rust-gdb -iex "add-auto-load-safe-path /absolute/path/dbg-visualizer" /absolute/path/dbg-visualizer
```

使用 `rust-gdb` 同时加载 Rust 工具链原有 formatter。裸 GDB 也可以运行本组件，但可能没有标准库 formatter，并提示工具链自动加载脚本缺失。

开发时可手动刷新源码适配器：

```text
source /absolute/path/dbg-visualizer/debugger/gdb/dbgvis_gdb.py
```

加载器替换旧的注册和事件处理器，防止重复挂载。它不是向任意其他二进制注入 Rust 支持的机制；目标仍需编入 runtime 和注册表。

### LLDB / CodeLLDB

```text
command script import /absolute/path/dbg-visualizer/debugger/lldb/dbgvis_lldb.py
dbgvis-install-hook
```

`dbgvis-install-hook` 在 target 创建后执行，在停止事件上按注册表更新专用 `dbgvis` category。配置变化也会立即更新 category。不要把它放在 target 尚未创建的 `initCommands` 中。仓库的 CodeLLDB 配置把导入放在 `initCommands`，把安装 hook 放在 `preRunCommands`。

`native` 模式不为类型注册新的 summary；结构化展开通过独立 synthetic provider 提供。已有原生 formatter 共存行为在集成测试中使用独立测试 category 验证。若一个已接管的 summary 执行失败，返回原始字段及错误标识，不冒充成功恢复了原来的 summary。

## 注册类型

依赖 `visualizer-runtime`，在程序中集中调用一次注册宏。以下使用真实 API：

```rust
#[derive(Debug)]
struct MyValue { count: usize }

visualizer_runtime::register_visualizers! {
    MyValue => { name: "my_app::MyValue", debug },
    bytes::Bytes => {
        name: "bytes::bytes::Bytes",
        debug,
        children: visualizer_adapters::BytesElements
    }
}

fn main() {
    visualizer_runtime::retain(&DBG_VIS_MODULE_V1);
    // 业务代码
}
```

`name` 必须为目标调试信息中的完整类型名；可选 `aliases: ["GDB 完整名称", "LLDB 完整名称"]` 用于调试器的命名差异。宏生成具体类型函数指针，无需新增 Python 字典项或 FFI 导出。`display` 要求该类型实现 Display，能力不满足时编译失败。

为带泛型的类型登记具体实例。示例中登记 `IndexMap<i32, &str>`，并显式声明 `i32` / `int`、默认 hasher 的名称差异。只规范化空白，不对类型名称做不加区分的子串替换。类型所属模块、完整名称、大小和可用的对齐信息共同用于检查；不匹配或有歧义时不执行。

注册本身不提供运行时内存安全证明。对象必须仍然存活、满足其不变量，并允许共享借用。带引用类型的适配器只可在本次调用中借用，不得因为生命周期在调试信息里被擦除而保存引用、假设数据为 `'static`；示例与测试使用了局部 String 借出的 `&str`。

`retain` 必须被真实可达代码调用，用于保留 descriptor、dispatcher 及它们引用的具体实现。已验证 release 和 LTO 最终产物，不依赖 `#[used]` 单独保留。

本仓库演示通过 `visualizer` feature 控制接入，默认开启。关闭演示的全部桥接代码：

```sh
cargo build --no-default-features
```

其他项目可把 runtime/adapters 作为可选依赖并采用相同模式；脚本可手动加载。若要把 GDB 脚本嵌入自己的产物，复用本仓库 `build.rs` 的打包流程及对应 Python 源文件。

## 容器与字段适配

实现 `unsafe trait Children<T>`：声明 `SHAPE`，提供 `count` 和按 `(start, count)` 请求填写描述符的 `page`。注册时使用 `children: Adapter`。

安全要求：返回真实、稳定存储的字段/元素地址；对象恢复执行后这些地址立即失效。禁止返回临时局部值的地址。`Child::borrowed` 为有地址的字段生成类型、大小和对齐信息；`Child::string` 额外记录实际 `&str` 槽及字符串数据范围；`Child::scalar` 将计算得到的 u64 直接复制进描述符，前端生成无目标地址的标量值。名称最多 63 字节，类型名最多 191 字节；超长时报错，不截断成另一个类型名。

首批实现：

- Bytes：使用公开切片接口枚举 u8，保留切片偏移与共享存储语义。
- IndexMap<i32, &str>：使用 `get_index` 按插入顺序返回实际 key/value 槽。
- 示例 Point / Record：用适配器枚举字段，包含嵌套 Bytes、Point 和循环引用指针。

GDB map 使用键值交替子项及 map display hint。LLDB / CodeLLDB 使用 `[i].key`、`[i].value` 平铺节点；每个节点保留实际类型和值地址，不伪造连续键值结构。

超过自动展示上限时显示省略节点，使用 `dbgvis page` 查询后续页。每页最多 64 个逻辑元素，map 最多返回 128 个描述符。子元素不要求登记 Debug / Display，没有登记时沿用原有值显示。

本组件只枚举直接子项，不预先遍历对象图；指针保留为指针，后续展开由调试器逐层请求。循环引用的展开深度由 GDB 的 `set print max-depth N`、LLDB 的 `frame variable -D N` / 前端展开动作控制，不使用全局地址去重，因此共享对象可以在不同路径显示。Python 与 Rust 分别阻止同一目标调用中的 formatter 重入。

## 缓存、错误与恢复

GDB 不持有跨请求的值缓存；一个 children 迭代器只保存其当前页。LLDB synthetic provider 保存有界页缓存，进程、包含表达式执行的 stop ID、组件调用计数、配置代次或原始对象头变化时失效。子值总是从真实地址重新构造。

LLDB 无法从 Python 可靠监听所有外部内存写入。对本仓库内置适配器，页成员和存储位置来自对象头；额外读取对象头用于发现同一次停顿中的变化。自定义适配器如果依赖对象外部的可变全局状态，调试器写入该状态后应执行 `dbgvis refresh` 并重新请求视图。超过 4096 字节的根对象不复用页缓存。

`dbgvis status` 返回最近的错误、调用次数、按操作分类的次数和累计时长。目标调用异常或响应序号不一致时，将该进程标为不可继续主动格式化；`refresh` 和 `reset` 不解除这个状态，重启进程后才恢复。不能通过清除 Rust busy 标志“修好”被中断的调用栈。

`panic=unwind` 的 panic 在 C ABI 内侧捕获，panic hook 仍会运行；如果 panic payload 的析构再次 panic，第二个 payload 会被有意泄漏以避免越过 C ABI。`panic=abort`、非法内存访问及目标退出不能恢复。超时和恢复寄存器不撤销用户 fmt 已产生的副作用。

core dump、无可寻址存储的值、ABI 不兼容和未注册类型使用原生视图。不要复制对象字节到临时区域后假装它仍是原对象。
